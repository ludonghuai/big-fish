## 一、总目标

本档是桌面壳板块（Bigfish 桌面端「壳」层：启动形态 / 托盘 / 窗口 / 桌宠交互入口 / 更新门禁）需求的唯一权威源。**板块级总目标**：

让使用桌面端（验收目标平台为 Windows）的用户，在「壳」这一层获得安静、清晰、符合直觉的使用体验——**启动安静**（冷启动只出桌宠与托盘，不自动弹出任何窗口）、**入口清晰**（桌宠左键打开主界面、右键打开兑换屋，两条链互不串；托盘菜单按使用频率与视觉习惯组织、所有窗口入口可达）、**无冗余步骤**（删除不配置任何东西的新手向导）、**双态一致**（dev 与安装版的更新门禁口径可解释、可复现）；并且壳代码**结构可控**（`main.js` 按域拆分，修改任一域不必通读全档）。

**B06 批次的任务目标（原文保留）**：整合项目启动与桌面壳交互——启动形态 / 桌宠左右键语义 / 新手向导删除 / 托盘菜单重排 / 更新门禁口径 / `main.js` 拆分。

**追加工作项（F7，2026-09-16 主 agent 裁定；依据 = 用户指示「删 1-5」）**：无用文件清理——删除跑不起来的一次性脚本、逐字节重复的背景图与 0 引用的旧贴图（保留面清单见 US-8）。

**B07 批次的任务目标（2026-09-17）**：Harness ≥ 0.1.5 会话鉴权兼容（主窗口 URL）· 后端不拉起系统浏览器 ·
空闲检测不阻塞主进程 · F6 拆分遗留缺陷修复 · B06 收尾核销。

**板块级总目标的 B07 延伸**：壳与 Harness 的对接**以进程输出为契约**——版本差异（是否带 `?token=`）不写死在壳里，
靠读后端打印的地址适配；壳的主进程**不因周期性检测而停顿**——陪伴功能不得成为卡顿源。

## 三、功能用户故事

格式：**作为一个 [角色]，我想要 [功能]，以便 [目的]**。
本条验收回指 `docs/batches/B06-shell-ux.md` §1.5 的 AC1…AC7（编号取自该节）。

### US-1 桌宠左键 = 打开 / 聚焦主界面（只开不隐）（验收：AC1）

作为一个使用桌宠的用户，我想要左键点击鲸鱼娘时主界面**显示并聚焦**（而不是隐藏已打开的主界面），以便「想打开」的点击永远不会把界面藏起来。

- 背景：现状为显隐切换（toggle）——主界面已打开时点击桌宠会把它隐藏。
- 边界（不做）：不做显隐切换；不改动点击 / 拖动的判定阈值（位移 > 5px 判为拖动，承 `docs/requirements/PET.md` US-5）；点击后的台词与开心动画保持。
- 备注：本条「只开不隐」为主 agent 裁定 R3，待用户在设计评审时追认（`docs/batches/B06-shell-ux.md` §1.9）。

### US-2 桌宠右键 = 只开兑换屋（与左键链互不串）（验收：AC1）

作为一个使用桌宠的用户，我想要右键点击鲸鱼娘时只打开兑换屋、主界面的显示状态保持不变，以便一次右键不再同时冒出主界面与兑换屋两个窗口。

- 背景：现状右键松开同时触发左键链（一次右键同时出现主界面与兑换屋——既有语义缺口，`docs/design/PET-DRAG.md` §2.5 观察项 F2 / 技术待办 T1）。
- 边界（不做）：不改兑换屋窗口自身内容与定位策略（跟随桌宠的既有逻辑保持原样；专注模式下无桌宠时窗口落系统默认位置）。

### US-3 删除新手向导（验收：AC3）

作为一个使用桌面端的用户，我想要启动时不再出现「新手向导」窗，以便不被一个不配置任何东西、只把用户指去别处照做的窗口打扰。

- 依据：向导第 3 步原文即「把 Key 填进软件自带的设置」；harness 自带模型 / API Key 设置与首启引导（证据见设计档 §2.2.4）。
- 首启无 Key 路径（交代）：冷启动只出桌宠 + 托盘（承 US-5）→ 点击桌宠或托盘项打开主界面 → 按 harness 自带「设置 ▸ 模型 / API Key」完成配置。
- 边界（不做）：不重造任何替代向导 / 弹窗；托盘不新增「设置 API Key」项（用户裁定，`docs/batches/B06-shell-ux.md` §1.3 C2）。

### US-4 托盘菜单重排（验收：AC4）

作为一个使用托盘的用户，我想要托盘右键菜单按使用频率与视觉习惯组织——高频动作在前、模式提为一级、设置项归一组、危险操作隔离在「高级」子菜单、退出收尾——以便右键菜单一眼可用、符合视觉习惯。

- 可达性（硬要求）：专注模式下桌宠被销毁（桌宠右键链不可用）⇒「鲸鱼娘兑换屋」必须在托盘菜单有入口（一级项）。
- 边界（不做）：一级项 ≤ 12；不删任何既有能力（含 Windows 右键菜单安装 / 卸载、自动检查更新、任务完成通知、开机自启、找回鲸鱼娘）；不改托盘图标左键行为（保持主界面显隐切换）。

### US-5 冷启动形态 = 桌宠 + 托盘（主界面不自动显示）（验收：AC2）

作为一个使用桌面端的用户，我想要冷启动时只出现桌宠与托盘、主界面不自动弹出，以便启动不再被多余的窗口打扰——主界面按需打开（桌宠左键 / 托盘项 / 快捷键）。

- 边界（不做）：不改「是否启动后端」（后端照常启动，只改「是否显示窗口」）；不改「关闭主界面 = 隐到托盘」的既有语义；不改 `--open` / 第二实例 / 全局快捷键的显示路径。
- 备注：本条（C4 / R2 裁定）为主 agent 裁定，待用户在设计评审时追认（`docs/batches/B06-shell-ux.md` §1.9）。

### US-6 更新门禁口径（dev / 安装版双态）（验收：AC5、AC6）

作为一个在本地运行 Bigfish 的用户，我想要 dev 下不再出现「只在安装版可用」这类限制显示、并且 Harness 的检查与更新在 dev 同样可用（且真生效），同时安装版保留 App 自更新，以便两态行为一致、可解释、可复现。

- 口径（本条为权威口径；`docs/requirements/UPDATE.md` 中「dev 不检查 / 不更新」的旧条文已按本口径修订注记）：
  - **App 自更新面**：仅安装版可用。dev 下不执行、不显示、不弹窗（无任何 App 面的可见物）；相应跳过记日志。
  - **Harness 面**：dev 与安装版同口径放行——检查（手动 + 自动）、下载、安装、激活、回滚照常；dev 的 `dshBinPath()` 与打包分支同口径（活跃指针优先，兜底各自出厂副本），使 dev 的 harness 更新真生效。
  - **安装版行为不变**（`docs/batches/B06-shell-ux.md` §1.5 AC6）。
- 边界（不做）：不改 harness 检查的既有节奏（启动一次 + 6 小时轮询 + 托盘手动）与自动检查开关语义；不改门禁的 in-flight 守卫；不新增「只在安装版可用」类提示的替代文案。

### US-7 `main.js` 拆分（验收：AC7）

作为一个维护者，我想要 `main.js` 按功能域拆分为高内聚模块（拆分后每文件 < 500 行），以便修改任一域不必通读 2831 行、单文件体量债清零。

- 边界（不做）：不动 `market.js`（500 行贴线未超）；不顺手做任何行为变更；不引入构建器 / ESM 改造；不改 `package.json` 的依赖段。
- **B07 补注（2026-09-17；技术待办 T12）**：F6 拆分遗留两处未绑定引用——托盘「更换背景…」「恢复默认背景」所经的 `shell-mode.js` 调用了该档从未 require 的 `notifier`（该档只注入 `notify`）：
  `chooseBackground` 的异常被 `try/catch` 吞掉（只留一条假错误日志）、`resetBackground` 直接抛未捕获异常。属本条「行为零回退」口径下的缺口——B07 修复（走注入面 `notify`），并做同类未绑定引用全扫（期望 0 处）。
  验收 = `docs/batches/B07-harness-auth-compat.md` §1.5 AC5（设计档 AC14）。

### US-8 无用文件清理（验收：AC8；F7 追加项）

作为一个维护者，我想要删除仓库里跑不起来、无引用、重复或已被取代的文件，以便仓库不带「看似可用实则无效」的残留（残留即示范）。

### US-9 主窗口能打开 Harness 的会话鉴权 UI（验收：AC1、AC6）

作为一个使用桌面端的用户，我想要主窗口打开后直接显示 Harness 的对话界面（而不是一行 401 提示文字），并且在 Harness 换代（≥ 0.1.5 引入 web 会话鉴权）后仍然如此，以便「打开主界面」这一动作永远真的能打开界面。

- 背景：Harness ≥ 0.1.5 的 web 服务给浏览器侧加了会话鉴权——启动时打印带一次性令牌的地址（`dsh web: http://127.0.0.1:<port>/?token=…`）；
  必须先访问该地址换取签名 Cookie（绑定 host:port）才能拿到 UI；直接访问裸地址一律 401 + 文本 `dsh web authentication required; reopen the URL printed by dsh web.`（取证见设计档 §2.2.8）。
- 契约（做什么）：主窗口加载地址以后端启动输出行 `dsh web: <url>` 为**唯一来源**（回环主机 + 当前端口校验通过才采用）；后端重启（新端口 + 新令牌）后主窗口自动跟进新地址；地址未捕获时回落裸地址**并在日志留一条可检索的诊断行**（不静默白屏）；地址晚到（宽限耗尽后才命中）时同样自动跟进——已按裸地址加载的主窗口补一次加载到命中地址，使该次会话自行回到对话界面（不要求用户重启应用）。
- 边界（不做）：不改 Harness 内部代码（`dsh-bundle/` 与 `userData/dsh-update/versions/**` 只读）；不关闭 / 绕过鉴权（Harness 无此开关）；不自行推算或伪造令牌 / Cookie；不新增 Harness 未支持的启动参数；不把令牌值写入任何文档或新增日志行。
- 兼容性：旧版 Harness（`0.1.0-rc.6`，打印不带令牌的裸地址）下行为与既有版本一致（捕获行在、回落面不变）。
- 备注：本条代码已由他在途会话先行落地并经用户实机确认可用（`docs/batches/B07-harness-auth-compat.md` §1.3 C6 / §1.6 #11）——B07 为**设计补档 + 评审追认**，不重写实现。

### US-10 后端不再拉起系统默认浏览器（验收：AC2、AC6）

作为一个使用桌面端的用户，我想要 Bigfish 启动后端时不再额外弹出系统默认浏览器窗口（壳自带主界面就是入口），以便启动不被多出来的浏览器打扰。

- 依据：需求池 R7 转正（用户 2026-09-17 明确同意并入本批；原 2026-09-16「单独立条，以后做」撤销）。
- 契约（做什么）：后端以 `--no-open` 启动（`dsh --profile web` 的既有选项）——启动日志不再出现 `dsh web: opening the default browser; pass --no-open to disable`，实际无新浏览器窗口 / 标签页。该选项**只影响是否拉起浏览器**，不影响地址打印（US-9 的捕获链依赖该行继续在场）。
- 边界（不做）：不改 Harness 其余启动参数语义；不改主窗口 / 托盘 / 快捷键的打开路径；不为「打开浏览器」另设替代入口。
- 取证面（硬）：后端 stdout/stderr 改为管道后**必须双写 `bigfish.log`**——B04 / B05 的验收取证面（`harness activate …` / `harness install phase=…` 行）依赖该档，不得因本批改动丢失。

### US-11 空闲检测不阻塞主进程（验收：AC3、AC4）

作为一个使用桌宠的用户，我想要「任务完成」提醒的探测不拖慢主进程（拖动桌宠、点托盘、开窗口不出现周期性顿挫），并且提醒语义与原来一致，以便陪伴功能只在真的完成任务时轻轻提醒一次。

- 背景：旧实现每 5 s 在主进程同步递归遍历整个 `~/.dsh`（本机实测 **20,857 文件**，其中 `pnpm-store/` 占 20,849）⇒ 每轮阻塞 ≈2 s，表现为周期性卡顿。
- 契约（做什么）：Windows 走 `fs.watch(recursive)` 事件推送（OS 级监听，零遍历）；其余平台走异步扫描回落（不阻塞）；5 s 定时器回调只做空闲判定的纯算术（无文件系统 I/O）；「任务完成」语义保持——后端写入期不误报、空闲达阈值后通知**一次**、`notifyOnComplete=false` 时零通知（且关闭期间的活动不在重新开启时补报）。
- busy 判定面（口径）：`~/.dsh` 下**路径任一段落**为 `profiles` 或 `node_modules` 的写入不计忙（= 旧实现的 skip 语义原样保留）；其余写入计忙。
- 边界（不做）：不改通知文案 / 阈值（`IDLE_NOTIFY_MS` = 30 s）/ 托盘开关语义；不新增依赖（含 `chokidar`）；不新增常驻日志（诊断行只在监视器注册失败或运行期异常时发）。

## 四、非功能标准

### NFR-1 启动与首启可用性（验收：AC2、AC3）

- 冷启动（whale 模式）序列中，除桌宠窗与托盘外**不得出现任何自动可见的窗口**（向导窗与主界面均不自动显示）。
- 首启可达性：无 Key 用户从冷启动到达「模型 / API Key」配置入口的路径 ≤ 2 步（打开主界面 → 设置），且每一步都有可达入口（桌宠左键 / 托盘项）。
- 度量方式：真机窗口枚举 + 显示路径清单静态核对（设计档 §2.2.2）；首启路径真机走查。

### NFR-2 兼容性

- Windows 为验收与验证目标平台；macOS / Linux 既有行为不得回退。
- 本批的启动形态（US-5）与托盘结构（US-4）变更为**跨平台有意变更**（纯 Electron 共有 API、无平台分支），不属于「回退面」；macOS `activate`（Dock 点击）统一改经 `showMainWindow()`（用户主动显示请求：显示 + 聚焦；零窗口时建窗后显示）——**有意变更**，同样不属于「回退面」；`activate` 之外的 macOS / Linux 既有行为不得回退。
- 既有 win32 分支（穿透开关、Windows 右键菜单）保持原样。
- **B07 注记（2026-09-17）**：本批新增的后端输出捕获 / 双写 / `--no-open` 路径**零平台分支**（纯 Node 流 API + Harness 既有选项）；空闲检测在非 Windows 平台走**异步扫描回落路径**（不因平台分支回归、不阻塞）。
- 度量方式：评审逐条核对设计档 §2.3 受影响文件表与 §2.5 冲突点核对表；`grep` 平台分支计数不变（新增代码零平台分支）。

### NFR-3 可维护性（拆分口径；验收：AC7）

- 拆分后**全仓 JavaScript 单文件 ≤ 500 行**（含既有文件；现状超顶者仅 `main.js` 一处 2831 行，拆分后清零）。
- 零新依赖（`dependencies` 保持空数组）、不新增构建步骤（源码直接可运行）。
- 既有取证锚点不丢：`pet-drag.log` / `pet-geometry.log`（B01/B03）、`updater.log`（B02/B04/B05，含 15 条主格式行与变体）、`market.log` / `exchange.log` / `bigfish.log`、console 行、env 开关（`BIGFISH_PET_DEBUG` 等）——字符串与发射点逐条保持；拆分自身不新增 / 不删除日志（US-6 新增的 `update gate … face=app skipped=dev` 为唯一新增行）。
- **B07 注记（2026-09-17）**：`bigfish.log` 的取证面契约扩展为「后端 stdout/stderr 双写 + 壳侧启动横幅行 + 本批新增的地址捕获 / 未捕获诊断行」（设计档 §2.2.9）；`dependencies` 保持空数组、不引构建步骤；本批**零新增文件** ⇒ `package.json` 的 `build.files` 不动。
- 度量方式：行数实测（换行符计数口径，定义见 `docs/design/SHELL-UX.md` §2.3 行数口径注）+ `node --check` 全绿 + 锚点清单逐条 `grep`（设计档 §3.3）+ `package.json` 依赖段零 diff。

### NFR-4 双态可解释性（验收：AC5、AC6）

- dev 与安装版的差异**只允许**两处：① App 自更新面（仅安装版）；② 出厂副本兜底路径（dev = `dsh-bundle/`，安装版 = `resourcesPath/dsh`）。除这两处外两态同口径。
- 度量方式：门禁分支与路径分支静态核对（设计档 §2.2.5）；dev 实跑对照 `updater.log` 行。

### NFR-5 主进程响应性（空闲检测域；验收：AC3）

- 5 s 周期回调路径内**不得出现任何同步文件系统调用**——判据 = 探测模块全文无 `*Sync(` 调用面（死代码同判：不留同步遍历实现，残留即示范）。
- 探测开销与 `~/.dsh` 规模解耦：Windows 主路径为 OS 级事件推送（不为每个文件做 `stat`）；回落路径为异步扫描（不阻塞事件循环）。
- 度量方式：静态判据（`grep` 于 `shell-notify.js`：`*Sync(` = 0 处）+ 真机（本机 `~/.dsh` 20,857 文件下，桌宠拖动 / 托盘点击 / 开关窗口无可感周期性顿挫；旧实现对照 = 每 5 s ≈2 s 阻塞）。
- 适用范围：Windows 为验收平台；非 Windows 走异步回落路径，同样满足「无同步调用」判据（不要求事件推送语义）。
