## 一、总目标

本档是桌宠板块（鲸鱼娘）需求的唯一权威源。**板块级总目标**：

让使用桌面端（验收目标平台为 Windows）的用户，**在任意显示器布局下**（单屏、多屏、各屏分辨率与缩放比不同）都能稳定地使用桌宠——她始终**看得见**（不会因几何错误落到无显示器覆盖的坐标）、**拖得动**（跨屏拖动跟手、不错位）、**大小稳定**（跨屏不出现视觉大小跳变），并且意外发生时用户可一键找回；同时不牺牲任何既有交互。

**B01 批次的拖拽跟手目标（原文保留）**：让使用桌面端（本批验收目标平台为 Windows）的用户在拖动桌宠「鲸鱼娘」时，窗口与鼠标光标严格同步、完全跟手、无可感延迟，同时不牺牲任何既有交互。

**B18 批次的动画链目标（原文保留）**：让使用桌面端的用户在盯着桌面挂件看时，看到的是**连续的动作**（待机 / 转向 / 移动 / 随机小动作按设定比例自然衔接），而不是定格的一张图；动作切换时**不出现空白、闪白或跳帧**；点击、喂食、入睡等时刻按「档位」从候选动作里挑一段播且不连播同一段；素材升级可**安全回退**（素材缺失即退回既有逐帧 PNG 通道）；系统声明「减少动态效果」时如实让步（不做淡入与浮动动效）。

**B19 批次的工作状态联动目标**：让使用桌面端的用户**不切窗口也能看出模型正在干活**——DSH 会话进行时，桌宠按当前工作性质切到对应动作档（**模型生成中 / 工具执行中 / 回合收尾**），并在需要时用一句短话（气泡）说明当前状态；该能力**只读** Harness 已落盘的数据（不写入、不安装插件），**默认不改变**既有观感与交互（开关可开可关）。

**B20 批次的物理手感与位移仲裁目标**：让使用桌面端的用户在拖着鲸鱼娘甩动并松手后感到她**有质量**——松手速度决定抛出的方向与力度（抛物线飞出），碰上屏幕边界或地面会**反弹**，落地后在摩擦下逐渐停下，撞击瞬间有 **Q 弹挤压**的形变反馈；同时保证**任一时刻只有一个来源在写窗口位置**（拖拽 / 物理 / 散步三者互斥的**单写者仲裁**），几何纪律（只在离散停泊点做尺寸校正与位置落盘）不回退——**关掉物理时，她与今天逐位一致**。

**B21 批次的动作选择目标**：让使用桌面端的用户在她**自己演示**的动作（个人动作）与他**亲手触发**的动作（交互动作）之间看到明确分界——他触发的动作（点击 / 喂食 / 拖动她 / 把她拖到屏幕边界松手逃跑）**一触即演**、可以打断她正在演的动作，而她自己在演的动作**不会**把他的交互反馈顶掉；两段动作之间**衔接丝滑**（不在交界处先停住再从头起）；被拖到屏幕边界的**逃跑动作正确、一次逃跑连贯不反复重来**。

**B27 批次的观感 II 目标（原文保留）**：让使用桌面端的用户觉得桌宠**安静陪着**而非「忙个不停」——她**隔三岔五**才表演一个动作（动作之间有一段安静的待机呼吸）；被拖到屏幕边界的**逃跑看得出是逃跑**（跑得明显、逃跑姿态保持完整一段再自然收尾、被拖着时是「被抓」的惊吓样而不是星星眼）；甩抛 / 散步的活动范围按**可见身体**贴到工作区上 / 左 / 右三面（与底面同口径，身体真贴边而不是隔着透明留白停住）。

**B31 批次的好感度数值重平衡目标（原文保留）**：让等级与喂食在数值上真正有意义——修掉「一个任务直接满级、满级后点数无上限溢出、零食给的量小到无感」三处体感缺陷：**等级仍 10 级**、阈值绝对值大幅调高（一次长任务不直接满级，满级 = 长期深度使用的顶点）；喂食重定效率成为**有意义的加速路径**（保持「喂食 = 被动 2 倍」的正确汇率，量级对齐新曲线）；满级分支定义清楚（点数显示 MAX 不溢出、播报收敛）。

**B23 批次的动作解锁与图鉴目标**：让桌宠的动作池**随「时间」与「陪伴」生长**——节日到了她做节日的事（一年只此一窗，其余时间锁死）、到了饭点她吃饭（一天一次、过点不补）、好感度升级解锁新动作（看得见的「她越来越丰富」，让用户有收获感）；同时给用户一张**动作图鉴**（右键弹窗的第二标签卡）：每条动作是什么、解锁条件是什么、整体解锁进度到哪了。三把锁全部**可关**、**默认全开**（直接启用解锁玩法——用户 2026-09-20 裁定）；锁住的段**绝不入选**（硬排除，不是权重调零）。

**B35 批次的右键弹窗重做与图鉴卡片化目标**：让右键弹窗从「320×500 固定小窗 + 纯文字清单」重做为一扇**可调整大小、精心设计**的桌宠面板——喂养面布局重排（余额 / 好感头部卡 + 食品卡片化），图鉴升级为**视频卡片墙**（每动作一张卡、直放 webm、可见即播 / 离屏即停、有收集感——用户 2026-09-20 裁定 D-1）；
用户在图鉴里**喜欢**动作（星标收藏 + 更常出现 + 置顶成组 + 只看喜欢——D-2）与**屏蔽**动作（随机轮换池与事件触发全排除，独占事件唯一段除外——D-3）；满级（Lv.10）玩家获得**无视时间限制**的自由特权（时节窗口 / 饭点窗口 / 一天一次三者全解除——D-4）；喜欢 / 屏蔽集合与窗口尺寸**落盘持久化**，重启保留。

## 二、范围

本档按批次分层登记桌宠在桌面上的**可用性与几何**需求：

- **B01（拖拽跟手）**：US-1…US-8、NFR-1…NFR-4——已实现，本档原文保留；
- **B03（多屏几何与可见性）**：US-9…US-14、NFR-5…NFR-8——跨屏活动与所在屏边界口径、松手可见性校正、混合 DPI 视觉一致性、跨屏拖动无错位、位置持久化与显示器配置变化回落、找回入口；
- **跨批不得回退项**：US-1…US-8 与 NFR-1…NFR-4 的任何条目，后续批次（含 B03）均不得回退。
- **B18（动画链引擎）**：US-15…US-19、NFR-9…NFR-13——动画池与权重链、双缓冲交叉淡入（切换无空白帧）、事件档位动画、视频素材接入（保留 PNG 通道与回落）、`prefers-reduced-motion`。**范围边界逐条写在各用户故事内**；本批不动物理手感 / 会话事件联动 / 多实例 / 素材生成链（见下表「明确不包含」）。
- **B19（工作状态联动，外部项目移植 D1 面）**：US-20…US-23、NFR-14…NFR-17——把 DSH 会话的真实工作进程映射为桌宠动作档位（生成中 / 工具执行中 / 回合收尾）+ 可选状态气泡 + 开关面；**档位集合以本仓只读数据面的可观测能力为界**（样本的「等待批准 / 回合成功 / 回合失败」三档不可观测 ⇒ **用户 2026-09-18 裁定本批为可观测三档**；见 US-20 口径与设计档 §1.3.5 / §2.11 观察项 O11–O13）；**六档的补齐 = 事件桥后置批 B22**。
- **B20（物理手感 + 位移仲裁，外部项目移植 B 面 · 含 O10 位移接管裁定面）**：US-24…US-28、NFR-18…NFR-22——甩抛与飞行（重力 / 边界反弹 / 落地摩擦 / 静止收敛）、撞击形变反馈（Q 弹）、**位移单写者仲裁**（拖拽 / 物理 / 散步的写权归属、优先级与交接）、物理开关与默认值、停下即停泊与降级面。**范围边界逐条写在各用户故事内**；**位置写权优先级口径 = 拖拽 > 物理 > 散步**（动画侧的档位优先级口径另见 US-21，两套口径解耦）。
- **B26（观感修正：工作档可见性 + 落地口径 + 气泡节流）**：**不新增 US / NFR 条目**——对 **US-21**（自主触发让位 = 档位保持）与 **US-24**（落地口径 = 可见脚底）各补一条 B26 口径，并**修订 US-22 的节流口径**（按档 + 跨档全局下限）；来源 = 用户 2026-09-18 实机观察 + 台账 R19 / R20（批次档 `docs/batches/B26-pet-feel.md` §1.4 / §2.10）。
- **B21（动作选择规则：交互 / 个人动作分离 + 丝滑衔接 + 逃跑槽修复）**：US-29…US-31、NFR-23——交互动作（点击 / 喂食 / 拖动 / 拖到边界松手逃跑）与个人动作（她自己演示的）的分类与优先级、动作之间的衔接（段末前起下一段）与拖到屏幕边界的逃跑动作正确性。本批 = **B18 真机反馈的修复批**（`docs/batches/B18-pet-animation-chain.md` §6.6 的两处「不通过」）；**范围边界逐条写在各用户故事内**；不动物理手感（B20 面）、散步 / 位移节奏、会话事件联动、素材生产（见下表「明确不包含」）。
- **B27（观感 II：节奏 / 逃跑表达 / 抛掷边界三面）**：US-32…US-34、NFR-24…NFR-25——动作节奏改「隔三岔五」（加权待机 + 真·静默期）、逃跑与拖拽表达力（逃跑腿参数 / 播完整段 / drag 换段）、抛掷 / 散步活动范围上 / 左 / 右三面按「可见身体」口径（四面 insets 单点常量）；并对 **US-15 / US-29 / US-31 / US-24** 各补一条 B27 修订注记。来源 = 用户实机观察 + 台账 R21 / R22 / R23（批次档 `docs/batches/B27-pet-feel-2.md` §1）。
- **B31（好感度数值重平衡：等级阈值 · 喂食汇率 · 满级分支）**：US-35…US-37、NFR-26——等级曲线重定（10 级不变，阈值表由设计轮给出并经用户审）、喂食重定（保持 2× 汇率、量级对齐新曲线）、满级分支（MAX 显示 / `pointsToNext`=MAX / 播报收敛）与老数据迁移口径（接受重映射）。来源 = 台账 T48 + T49（批次档 `docs/batches/B31-affinity-balance.md` §1）；本批**不动** R16 等级门映射（B23 面）、不加新食品 / 货币 / 机制、不改兑换屋窗口结构。
- **B23（动作解锁三把锁 + 动作图鉴，本仓原创需求 R16）**：US-38…US-43、NFR-27…NFR-29——**时节门**（`[节前 6 天, 节后 3 天]` = 含节日当天共 10 天，2026–2035 离线节日表）、
  **饭点门**（三餐窗口 / 一天一次 / 过点不补）、**等级门**（10 级映射表 D-3）、**可选集硬排除**（锁住的段绝不入选）、**解锁提示**（一次可见提示）与
  **动作图鉴**（右键弹窗第二标签卡：动作 / 解锁条件 / 解锁百分比）。**默认三把锁全开**（直接启用解锁玩法——用户 2026-09-20 裁定）；时间源 = 本机系统时间（零网络校时）。
  **范围边界逐条写在各用户故事内**；来源 = 批次档 `docs/batches/B23-pet-action-unlock.md` §1（用户 2026-09-18 原话 + D-1…D-3 裁定）。
- **B35（右键弹窗重做与动作图鉴卡片化，本仓原创需求 R24）**：US-44…US-50、NFR-30…NFR-33——**窗口形态**（`resizable` 放开 + 最小 / 默认尺寸 + 尺寸持久化 + 贴宠位置自适应）、**喂养面布局重做**（头部卡 + 食品卡片化，与图鉴同一套视觉语言）、**图鉴视频卡片墙**（直放 webm、可见即播 / 离屏即停 / 懒加载、并发 ≤8、收集进度头）、
  **喜欢体系**（星标 + 类内选段加权 ×3 + 收藏组置顶 + 「只看喜欢」合取过滤）、**屏蔽体系**（随机轮换池与事件触发全排除、独占事件唯一段保护、温和切换）、**Lv.10 特权**（时节窗口 / 饭点窗口 / 一天一次三者全解除，默认生效可关）、**偏好持久化**（`userData/pet-prefs.json` + 窗口尺寸入 settings）。
  **范围边界逐条写在各用户故事内**；来源 = 批次档 `docs/batches/B35-pet-gallery-ui.md` §1（用户 2026-09-20 原话 + D-1…D-4 裁定）；承 B23 的门控与图鉴数据面（`pet-unlock-core.js` / `unlock:view`），Lv.1–Lv.9 门控语义与 B23 交付态**逐位一致**（桩测断言）。

- **工作状态的「等待批准 / 回合成功 / 回合失败」三档**——本仓只读数据面不可观测（证据见 `docs/design/PET-ANIMATION.md` §1.3.5 / §2.11 观察项 O11–O13）：等待批准与「工具在跑」在落盘数据上不可区分、回合成败（`turn/end` 的 `reason.kind`）不落任何持久行。
  要做须换事件源（Harness 侧事件桥 / 会话流订阅）= 新面另批——**去向 = 后置批 B22**（用户 2026-09-18 裁定：本批三档 + 六档另批）；本批**已预留扩展面**（池段 `events` 可再增 3 键 + 判定门可扩档 ⇒ B22 到位后**增量补齐、不返工**），不在 B19 范围。
- **余额档位与气泡 / 碎碎念 / 对话与记忆（D2 面）· 物理手感（B 面）· 多实例与 pet pack（E 面）· 素材生产（C 面）**——B19 一律不做。
- **跨屏飞行**（甩抛后越过屏缝飞到另一块显示器）——本批飞行边界 = **她当前所在屏的工作区**（与散步「不跨屏」同源，见 US-24 边界）；逐屏 AABB + 空洞探测的跨屏抛掷属新面（`docs/design/PET-MOVEMENT.md` §2.5 观察项 O-1）；
- **多宠物互相碰撞**（样本 `physics.petCollision`）——本仓为单实例、单桌宠窗口，属 E 面另批；
- **用户可调物理参数**（重力 / 弹性 / 摩擦的界面化调值）——本批参数为代码内单一参数表（`docs/design/PET-MOVEMENT.md` §2.2.3），只给开关、不给调值；
- **飞行中的位置钳制**（飞行途中把窗口拉回工作区）——飞行轨迹本身锁在起飞时确定的屏内区间，位置校正只发生在停下的那一瞬（US-28）。
- **调整散步 / 位移节奏或折返序列以匹配动画段长**——B21 不做：`doWander` 的折返序列与其「仅 idle 态才起步」守卫是 B03 校准成果，属散步状态机面；「素材段长（≈10 s）长于位移段长（0.25–2.9 s）」这一固有张力由 B21 **登记为观察项**（`docs/design/PET-ANIMATION.md` §2.13 观察项 O22），不解决；
- **改自主小动作（待机随机表演）的触发源或节拍**——B21 不做：1.5 min 节拍 / 40% 概率 / 2.4 s 时长照旧；其「工作档期间让位」口径归 B26 面（US-21），本批不碰（分类按**触发面**读，同一池键两侧复用见 US-29 口径）。
- **动作解锁的门控数据进 `assets/pet-anim/pool.json`**——B23 不做：池校验 V1–V6 与双缓冲形态是 B18 冻结契约，加门控字段即改校验；门控数据面独立成档（`unlock-rules.json`），池档零 diff。B22（六档事件桥）与 B23 串行实施（B23 在后；冲突面与串行口径见设计档 §2.7）。
- **抽卡 / 成就 / 任务系统 · 网络校时 / 时区服务 · 多宠物共享进度**——B23 不做（时间源 = 本机系统时间；跨时区以本机为准）；解锁进度存 `userData`，多实例 / 多宠物共享属 E 面另批。
- **抽卡 / 成就 / 任务系统 · 多宠物 · 云同步 · 用户面动作导入**——B35 不做（图鉴卡片化 ≠ 抽卡玩法；动作导入归 B24 后置批）；喜欢 / 屏蔽集合存 `userData`，云端同步属 E 面另批。
- **卡片静态封面抽帧**——B35 不做（用户裁定 D-1 = 视频卡直放 webm，零新素材；ffmpeg 抽帧 = 新依赖，否决）；**主窗口 / 市场 / 更新面 UI 与托盘菜单结构**——B35 不动（图鉴入口仍 = 右键弹窗内标签卡，托盘只增两枚开关项）；**Lv.1–Lv.9 的门控语义**——B35 零变化（特权仅挂 Lv.10，桩测断言逐位一致）。

## 三、功能用户故事

格式：**作为一个 [角色]，我想要 [功能]，以便 [目的]**。
每条以「验收」标注对应验收条目——编号取自 `docs/batches/B01-pet-drag-follow.md` §1.5（AC1…AC9，已由用户确认）。

### US-1 拖动跟手（验收：AC1）

作为一个使用桌宠的用户，我想要在按住鲸鱼娘移动时她与光标保持严格同步（无可感滞后、无脱离），以便获得与拖动原生窗口一致的拖拽手感。

- 边界（不做）：不做拖拽惯性、缓动、吸附等后置修饰——任何后置动画都与「跟手」直接冲突。

### US-2 拖出窗口矩形仍跟随（验收：AC2）

作为一个使用桌宠的用户，我想要在拖动过程中把光标移出桌宠窗口矩形（含一路拖到屏幕边缘）时她仍持续跟随，以便大幅拖动不会中途掉队或停住。

- 边界（不做）：不把窗口位置钳制在屏幕工作区内（允许一部分拖到屏幕外），与现状保持一致。

### US-3 松手即停且不粘连（验收：AC3）

作为一个使用桌宠的用户，我想要在松开鼠标后她立刻静止、且拖动状态一定被清空，以便随后的点击与拖动都能正常响应。

- 边界（不做）：不引入「松手惯性滑行」。
- **修订（B20，2026-09-18；类别 = 语义变更；待用户追认 = `docs/batches/B20-pet-physics.md` §1.5 的**本设计新增项 U-7**；源 = 同档 §1.2「做」/ §1.4-3）**：本条「松开鼠标后她立刻静止」自 B20 起收窄为「**拖动循环**在松手后立即停止写入」——用户开启物理手感（US-27）**且释放速度 ≥ 阈值 `T`**（起飞门）时，松手后由**物理**接管飞行（US-24），静止时刻 = 飞行的**收口时刻**（近地软着陆档 ≤ 4 s；其余档 ≤ 5 s 硬上界且**收口在地面**，见 NFR-19）。
  - **收窄（本轮修正，2026-09-18；源 = 用户裁定「很慢的话就急停，很快的话就扔出去」）**：**释放速度 < `T`（缓放 / 正常放下）时本条逐字照旧**——松手后 ≤ 200ms 内静止、物理面零写入（不起飞）；本条在「正常放下」这一主流用法上的语义**完全不变**。`T` 的口径 / 量纲 / 默认值与标定状态见 `docs/design/PET-MOVEMENT.md` §2.2.12。
  - 连带：「不引入松手惯性滑行」一句由「惯性只来自 US-24 的物理模型（不是任意滑行，且仅在释放速度 ≥ `T` 起飞后存在）」**取代**；「拖动状态一定被清空」与异常路径口径**逐字不变**；**物理关闭（默认）时本条逐字照旧成立**。

### US-4 拖动期间不被自主走动打断（验收：AC4）

作为一个使用桌宠的用户，我想要在长时间按住她不动时她不会自己走开，以便整个拖动过程完全由我控制。

- 边界（不做）：不顺带改动散步 / 睡眠 / 闲聊的既有触发节奏（非拖动期间行为保持现状）。

### US-5 原地点击仍唤起主窗口（验收：AC5；不得回退）

作为一个使用桌宠的用户，我想要在不产生位移的原地点击后仍然弹出主窗口并播放开心动画，以便点击唤起功能保持可用。

- 边界（不做）：不改动点击判定阈值（位移 > 5px 判为拖动）与主窗口显隐语义。
- **修订（B06，2026-09-16；类别 = 语义变更，源 = `docs/batches/B06-shell-ux.md` §1.3 C1 / §1.4 R3）**：点击语义由「显隐切换」改为「打开 / 聚焦（只开不隐）」——本条边界的「不改动主窗口显隐语义」自 B06 起收窄为「不改动点击判定阈值」；新语义权威口径 = `docs/requirements/SHELL.md` §三 US-1。

### US-6 右键仍打开兑换屋（验收：AC6；不得回退）

作为一个使用桌宠的用户，我想要右键点击时仍然打开兑换屋窗口，以便兑换功能保持可用。

- 边界（不做）：不改动兑换屋窗口的定位策略（其跟随鲸鱼娘当前位置的既有逻辑保持原样）。

### US-7 拖到边缘松手仍挣脱逃跑（验收：AC7；不得回退）

作为一个使用桌宠的用户，我想要把她拖到屏幕左右边缘松手时仍触发「挣脱逃跑」反应，以便这一既有彩蛋行为保持可用。

- 边界（不做）：不改动逃脱的触发阈值（距边缘 4px）与逃跑动作本身。
- **修订（B21，2026-09-18；类别 = 语义变更；源 = 用户 2026-09-18 原话「拖到边界的时候触发逃跑动作不太对，动作没正确切换」）**：本条边界的「不改动逃脱的触发阈值（距边缘 4px）与逃跑动作本身」自 B21 起收窄为「**不改动触发阈值与逃跑的方向语义**（往反方向跑）」——**动作的呈现**（选哪一段 / 衔接方式 / 一次逃跑内不重播）由 B21 修正；权威口径 = US-31 与 `docs/design/PET-ANIMATION.md` §2.13。

### US-8 拖动后尺寸不漂移（验收：AC8；不得回退）

作为一个使用桌宠的用户，我想要拖动结束后窗口仍保持 250×270（不出现尺寸回拉造成的视觉跳动），以便桌宠尺寸稳定。

- 边界（不做）：不删除既有的尺寸回拉 workaround，只调整其调用方式与频率。
  - **口径收窄（2026-09-16；类别 = 澄清，非语义变更）**：回拉职责保留（单一实现 = `petCalibrateSize()`），但判据由「与 250×270 判等」改为「读回值与锚点基线之差 ≤ 容差（8 DIP）」、调用频率改为「每跨屏事件至多一次 + 真漂移时一次」——口径与实证依据见 `docs/design/PET-MULTIMONITOR.md` §2.3.5-A / E。

### US-9 跨屏活动与所在屏边界（验收：B03 §1.5 AC1、AC7）

作为一个使用多显示器的用户，我想要把鲸鱼娘拖到任意一块显示器上之后，她的活动边界按**她当前所在的那块显示器**的工作区计算，以便她在副屏上也能正常走动，并且只有真正贴到**那块屏**的边缘时才会触发挣脱逃跑。（**澄清**：此「边缘」指**跨全部显示器的桌面并集外缘**；相邻显示器之间的屏缘不算墙角——口径依据见 `docs/design/PET-MULTIMONITOR.md` §2.1 E 组。）

- 边界（不做）：不做跨屏自主散步（散步不离开当前所在显示器）；不改贴墙判定的边缘阈值（4px）与逃跑动作本身。

### US-10 松手可见性校正（验收：B03 §1.5 AC2）

作为一个使用多显示器的用户，我想要在松手时桌宠窗口的中心点一定落在某块显示器的工作区内，以便把她放到屏幕交界、屏幕之间的空洞区或屏幕之外后不会丢失。

- 边界（不做）：不在拖动过程中做位置钳制（拖动仍允许越过屏幕边界，承 US-2）；不做「整个窗口必须完整落在工作区内」的更强约束——判据是**中心点**落在工作区内。
  - **澄清（2026-09-16；类别 = 澄清，非语义变更）**：窗口跨在两块**缩放比不同**的屏之间（骑线）时，松手会把窗口**推离交界、完全落入窗口中心点所在屏的 `bounds`**——这是消除「停留于混合 DPI 状态」的**独立规则**，与上述「中心点 / 工作区」可见性判据**正交**（窗口在 `bounds` 内即不触发，无论是否压任务栏）；推送与可见性校正**合并为同一次位置写入**。口径与判据见 `docs/design/PET-MULTIMONITOR.md` §2.3.7。
  - **澄清·续（2026-09-16；类别 = 澄清，非语义变更）**：**同一规则也适用于非拖动路径**——启动建窗后 / `ensurePet()` 重建的落点若骑线，按同一规则推离（该行为变更已获用户批准；口径与判据同上述澄清）。

### US-11 混合 DPI 视觉大小一致（验收：B03 §1.5 AC3）

作为一个各屏缩放比不同的用户，我想要鲸鱼娘在任一块显示器上的视觉大小一致、跨屏移动时不发生「变小 / 拖动又变大」的跳变，以便不必把各显示器的缩放比设成同一个值。

- 边界（不做）：不做「按屏保持物理像素尺寸恒定」的另一种口径（口径取舍见 `docs/design/PET-MULTIMONITOR.md` §2.1 B 组）；不改桌宠窗口的逻辑尺寸 250×270（DIP），也不改素材与画布尺寸。

### US-12 跨屏拖动无错位（验收：B03 §1.5 AC4）

作为一个使用多显示器的用户，我想要在拖着她跨屏移动的全过程中，光标与她被抓住的那一点不分离，以便跨屏拖动与单屏拖动的手感一致。

- 边界（不做）：不改 B01 的跟手机制（主进程按全局光标绝对定位的跟随循环）与其跟手指标（NFR-1）；不引入惯性、缓动、吸附。
- **口径限定（B20，2026-09-18；类别 = 澄清（**待用户追认 = U-7 的连带项**）；非新增需求）**：本条边界限**拖动过程**——跟手机制与其跟手指标零改动；松手**之后**的运动由 B20 的 US-24（物理模型）管辖，它不是拖动路径的后置修饰（本批对拖动路径**零改动**）。
  - **收紧（本轮修正，2026-09-18；源 = 用户裁定「很慢的话就急停，很快的话就扔出去」）**：上述「松手之后的运动」以**物理开启且释放速度 ≥ 阈值 `T`** 为条件（起飞门 = `docs/design/PET-MOVEMENT.md` §2.2.12）；**`v < T`（缓放 / 正常放下）时本条逐字照旧**（松手后 ≤ 200ms 静止、物理面零写入）。**物理关闭（默认）时本条逐字照旧成立。**

### US-13 位置持久化与显示器配置变化回落（验收：B03 §1.5 AC6）

作为一个使用桌宠的用户，我想要重启后她回到上次的位置，并且在我拔掉或更换显示器后自动回落到可见区，以便不必每次都重新把她找回来。

- 边界（不做）：不做按显示器配置分别记忆的多套位置档案；不做跨设备同步。

### US-14 找回入口（验收：B03 §1.5 AC5）

作为一个可能把桌宠弄丢的用户，我想要在托盘菜单里有一个「找回鲸鱼娘」入口，一键把她拉回可见区，以便几何再出意外时我能自救。

- 边界（不做）：不做全局快捷键与主窗口内的找回按钮；专注模式（桌宠窗口不存在）下该入口置灰不可用。

### US-15 动画池与权重链（验收：`docs/design/PET-ANIMATION.md` §3.1 AC1、AC2、AC3）

作为一个长时间把桌宠放在桌面上的用户，我想要她在没有人为干预时**连续地**表演动作（不是定格在一张图、也不是隔很久才动一下），动作之间按设定好的比例自然衔接，以便她看起来是「活着的」而不是一张贴纸。

- 边界（不做）：不做物理手感、不做多实例、不做素材生成链（见 §二「明确不包含」）；
- 边界（不做）：**窗口位移的驱动与节奏仍归既有散步机制**——权重链只决定「播哪一段动作」，不改位移的产生方式、速度与频率；
- 口径：动作池 = 可配置数据（随包文件），播放器只认「片段数组」这一抽象——池子规模与素材采用范围变化不改变实现。
- **修订（B27，2026-09-19；类别 = 语义变更；源 = 用户实机裁定「隔三岔五一个动作更好看」）**：本条「连续地表演（不是隔很久才动一下）」与用户 2026-09-19 裁定的节奏口径（US-32「隔三岔五」）**相抵** ⇒ 自 B27 起**节奏面按 US-32 读**（动作类段之后进入静默期，动作之间自然拉开）；本条其余断言（链机制 / 权重链 / 位移驱动归散步）逐字不变。设计回指 = `docs/design/PET-ANIMATION.md` §2.14。

### US-16 切换动作不出空白帧（验收：`docs/design/PET-ANIMATION.md` §3.1 AC4、AC5）

作为一个盯着桌宠看的用户，我想要她在两个动作之间切换时**看不到空白、闪白或跳帧**（上一段画面一直留在窗口里，直到下一段真正可播），以便观感连续、不被闪烁打断。

- 边界（不做）：不引入后处理转场（模糊 / 位移 / 缩放）；转场仅为新旧两段之间的一次短促交叉淡入，且在系统「减少动态效果」时关闭（见 US-19）。

### US-17 事件档位动画（验收：`docs/design/PET-ANIMATION.md` §3.1 AC2、AC6）

作为一个与桌宠互动的用户，我想要在点击、喂食、入睡等**特定时刻**看到与情境相符的动作，且同一情境下**不重复播同一段**（有多个候选时轮着来），以便互动反馈不呆板。

- 边界（不做）：本批只落「档位 → 候选数组 → 档内随机 / 轮换」机制与**既有触发点**（点击 / 喂食 / 入睡 / 随机小动作）的接入；会话事件（工作状态 / 余额 / 碎碎念 / 对话）接入属 D1 / D2 面；
- 边界（不做）：不改既有触发时机与阈值（点击位移阈值 5px、2 分钟入睡、1.5 分钟闲聊、喂食 2 秒回待机均不变）。

### US-18 视频素材接入（保留 PNG 通道）（验收：`docs/design/PET-ANIMATION.md` §3.1 AC7、AC8、AC9）

作为一个希望桌宠动作更生动的用户，我想要她既能播放**新的视频素材**（带透明通道、可透明叠加在桌面上），又能在素材缺失或出问题时**自动退回现有的逐帧 PNG 素材**（不空白、不报错、不出现打不开的窗口），以便这次升级是安全的、可回退的。

- 边界（不做）：不删除、不改写既有 PNG 素材与既有 CSS 尺寸口径（`#pet` 的 200px、旧待机帧 140px）；不改窗口逻辑尺寸 250×270（US-11 口径）；
- 边界（不做）：不做转码 / 压缩链（C 面）、不做用户自定义素材目录（另批）、不新增第三方依赖或原生模块。

### US-19 尊重「减少动态效果」（验收：`docs/design/PET-ANIMATION.md` §3.1 AC10）

作为一个在系统里开启了「减少动态效果」的用户，我想要桌宠**不播放淡入与浮动类动效**（动作本身照常变化，但不做渐隐渐显、不做上下浮动），以便她不会在我明确要求减少动态时仍然晃个不停。

- 边界（不做）：不因此停掉桌宠本身（不隐藏、不退出、不静默）——只停动效。

### US-20 工作状态动画反映真实会话进程（验收：`docs/design/PET-ANIMATION.md` §3.4 AC16、AC17、AC18）

作为一个让模型在后台干活的用户，我想要桌宠在会话进行中切到与当前工作性质相符的动作档——**模型生成中**播「思考」档、**工具执行中**播「忙碌」档、**回合收尾**播「整理」档——以便我瞥一眼桌面就知道她（模型）正在干活，而不是待机发呆。

- 边界（不做）：不做余额档位 / 碎碎念 / 对话（D2 面）、不做物理手感（B 面）、不做多实例与素材生成链（E / C 面）；
- 边界（不做）：**不向 Harness 写入任何数据、不安装 / 不加载 Harness 侧插件、不改 Harness 任何文件**——本批只**只读**读取 Harness 已落盘的数据（设计档 §2.8.1）；
- 口径（档位集合 = 读面能力所及）：本批落 **生成中 / 工具执行中 / 回合收尾** 三档（只读数据面的可观测证据见设计档 §1.3.5）。样本的「等待批准 / 回合成功 / 回合失败」三档在本仓只读数据面**不可观测**（同证据；不可区分性证据见 `dsh-agent-loop/lib/index.js:584-588` 与 `dsh-tools/lib/index.js:3314-3336`），本批**不实现**——**U-6 已裁定（2026-09-18）= 可观测三档**，六档的补齐 = **事件桥后置批 B22**（设计档 §2.11 观察项 O11–O13）；
- 口径：档位切换沿用 B18 的链规则（同档忽略、事件段播完才回链、多候选档在段末轮换）——工作档**不硬切**正在播的段。

### US-21 工作状态只作「底色」，既有交互与观感照旧（验收：`docs/design/PET-ANIMATION.md` §3.4 AC19、AC21、**AC24**）

作为一个已经习惯现有桌宠行为的用户，我想要点击、喂食、拖动、散步、入睡、台词等既有行为在开启工作状态后**一切照旧**，工作档只是这些行为之下的「底色」，以便新功能不改变我熟悉的手感与节奏。

- 边界（不做）：不改点击判定阈值（位移 > 5px）与左右键语义；不改拖动跟随与位移写入纪律（几何层零 diff）；不改散步 / 入睡 / 闲聊的既有参数（15–35 s / 2 min / 1.5 min）；不改既有 11 档语义与 PNG 通道口径；
- 口径（可观察的取舍，须落档）：工作档在途期间**不启动**散步——因果 = 既有「仅 idle 态才起步」的守卫上加一道工作档门（设计档 §2.8.4）；入睡不需要额外的门（既有 idle 守卫已覆盖）；工作档结束回落 idle 时重排入睡计时；
- 口径：优先级自高至低 = 拖动 > 散步 / 跑步 > 交互档（点击 / 喂食 / 随机小动作）> 工作档；交互档**可短时覆盖**工作档，结束后由「重断言」回工作档（≤ 1 s，设计档 §2.8.4）。
- 口径（**自主触发让位**，B26 追加；**修正轮 1 改向**；源 = 用户 2026-09-18 实机观察「工作模式的时候会穿插其它模式的动作，导致动作不明显，交替起来看不出来在工作」+ 批次档 `docs/batches/B26-pet-feel.md` §1.4 F1 / §2.10）：
  作为一个盯着桌面看她干活的用户，我想要工作档在途期间**她不要自己开始表演别的动作**（看书 / 星星眼 / 惊吓 / 开心这类待机随机小动作），以便我瞥一眼就能看出她确实在干活，而不是把「干活」与「自己玩」交替着演给我看（story 的可见性诉求同 US-20；本条落其**让位口径**）。
  口径（**让位窗口 = 记录新鲜期**）：在**选中会话记录新鲜**（`now − mtime ≤ WORK_STALE_MS`，60 s）期间，工作模块**不清档、不落 idle**，而是**维持上一档位**（= 「**档位保持**」）⇒ `petState` 恒为档位 ⇒ 自主随机小动作被**既有**「仅 `idle` 才起步」守卫挡住（**不新增门即达成目标**）。
  另保留一道**补漏起步门**（`playIdleVariant()` 首行加 `petBaseState() === 'idle'`，与散步起步门**同判据形态同常量来源**），覆盖「档位保持仍在而 `petState` 已回 idle、重断言被推迟」的窗口（**增量效力（修正轮 2 统一口径）= ≤1 s（交互档 / 走动档收尾间隙）＋ 拖动在途子情形（顺延至拖动结束后首个 tick）**；权威 = `docs/design/PET-ANIMATION.md` §2.12.3 ②）。
  **已在途**的交互档仍按既有优先级让工作档短时让位（≤ 2.4 s，随后重断言回工作档）——**不改优先级表与共同门名单**；权威口径 = `docs/design/PET-ANIMATION.md` §2.12（含效力边界与残余）。
  残余（射程外，如实登记）：① 首个工作档出现前（无「上一档位」可保持）；② **无选中记录**（读面 `unavailable` ⇒ 无新鲜度信号 ⇒ 不可保持）；③ **记录陈旧**（> 60 s）——三段清档照旧（与今天同形）。
  **语义代价（须用户批准时确认）**：**「会话开着但模型空闲」的时段也算作让位期**——这是 `WORK_STALE_MS`（60 s）口径的**固有含义**；若要更严（只在「回合在途 / 工具在跑」时让位）⇒ 需要**回合级信号** ⇒ 必须先有 Harness 侧事件桥（= B22 面）；本批不自作。
  保留面（**参数逐字照旧**）：点击 / 喂食 / 拖动等**用户输入触发**的交互；**闲聊台词**——其节拍参数（90 s / 40%）逐字未改，但**让位期内不弹**（`schedulePetChatter` 回调自带的 `petState === 'idle'` 守卫的自然结果，**非新增门**）。
  连带（观感，登记）：收尾档（`work-done`）的**可见时长**由「3 s 保持期」变为「保持到记录陈旧（≤60 s）或至下一档到来」——`WORK_DONE_HOLD_MS`（3 s）退为「紧接收尾档后记录立刻转陈旧」时的**下界**（设计档 §2.11 观察项 O19 改写）。

### US-22 工作状态气泡（可选、可关、可节流）（验收：`docs/design/PET-ANIMATION.md` §3.4 AC16、AC20、**AC31**）

作为一个忙碌的用户，我想要桌宠偶尔用一句短话告诉我当前进展（如「正在想下一步呢…」），以便不切到主窗口也能知道情况；同时我要能关掉它、且它不许刷屏。

- 边界（不做）：**不复用外部样本的文案**（含网络梗与毒舌向，且其来源受样本许可约束）——文案由本仓自写；
- 边界（不做）：不新增气泡控件、不改既有气泡元素与显示时长（4 s）——工作状态气泡走既有台词通道（后到者覆盖）；
- 口径（**节流，B26 修正轮 1 修订**；源 = 批次档 `docs/batches/B26-pet-feel.md` §2.10 / 设计档 §2.8.5）：节流 = ① 同一档位在一次连续停留内至多一条；② **同一档位**两条气泡间隔 ≥ 30 s；③ **任意两条（跨档）**间隔 ≥ 10 s（防三档连弹）；**回合收尾档不弹**（避开与既有「任务完成」提醒重复）；气泡内容不含任何会话内容（NFR-15）。
  - 修正理由（实测，源 = 设计档 §2.11 O21）：原实现为**跨档全局** 30 s 计数器 ⇒ 生成档进入必弹、**短工具调用（< 30 s）结构上不可见**（「工具在跑」档因此报不到）；改按档 + 全局下限后最坏 = 30 s 内 2 条（间隔 ≥ 10 s），仍守住「不许刷屏」。
  - **闲聊台词不纳入本节的节流**（两套计数器分离；闲聊无节流、走既有 4 s 显示）。

### US-23 开关面与默认值（验收：`docs/design/PET-ANIMATION.md` §3.4 AC20）

作为一个不希望桌宠行为被改变的用户，我想要这个功能有一个明确、可切换的开关，并且它的默认值对我保守，以便我升级后看到的桌宠与今天一致——除非我自己打开它。

- 口径：开关 = 托盘「设置」子菜单中的 checkbox（与既有「任务完成时通知」同形），取值持久化在 `settings.json` 的顶层布尔键（设计档 §2.8.6）；
- 口径（**U-1 = 采用推荐值：默认关**，待用户批准时一并确认；明细 = 批次档 §2.5）：**默认值** = **关**；设计档同源成文（设计档 §2.8.6 / DD-24；依据：样本 `workStatusEnabled` 注释明写默认关 + 保守默认）；如批准时改判 ⇒ 只需改一处默认值与本行；
- 口径：开关关闭 ⇒ 读面不启动（零日志、零监听）、当前工作档立即清空并回 idle。

### US-24 甩抛与飞行（验收：`docs/design/PET-MOVEMENT.md` §3.1 AC1、AC2、AC3、AC15、AC16、AC17、AC18、AC19、AC20、**AC21**、**AC22**）

作为一个拖动桌宠的用户，我想要在快速甩动后松手时她被**抛出去**（按松手速度决定方向与力度、抛物线飞行、碰上屏幕边界或地面反弹、落地后在摩擦下逐渐停下），以便她有「体重」而不是一块随手一甩就贴住的贴纸。

- 边界（不做）：不做**跨屏飞行**——飞行边界 = **她当前所在屏的工作区**（与散步的段起点口径同源，US-9「不跨屏」不回退）；不上屏间空洞、不出屏；
- 边界（不做）：不做「温柔放下」的抛掷——松手前停顿超过阈值（150 ms）或释放速度低于**起飞门阈值 `T`** 时按**原地放下**处理（不起飞，行为 = 今天）；
- 边界（不做）：不改窗口尺寸与形状——飞行只写**位置**；形变反馈走渲染面（US-25）；
- 口径（**起飞门**，本轮新增；源 = 用户裁定 2026-09-18）：门判据量 = **速度**（不是加速度）——取松手前 120 ms 采样窗内的**峰值速度** `v`（依据与候选否决见 `docs/design/PET-MOVEMENT.md` §2.2.12 / DD-16）；`v ≥ T` ⇒ 起飞；`v < T` ⇒ 不起飞（原地放下 = 今天的行为）；
- 口径（**静默放置**，本轮新增）：若松手前 120 ms 内位移接近 0（「挪到位 → 停一下 → 松手」）⇒ 一律判**放置**（不起飞）——单看末瞬速度会把这一常见动作误判为甩；
- 口径：`T` 量纲 = px/s，默认值 500，**可调单一常量 + 待实机标定**；权威口径（含量纲 / 标定路径 / 到期条件）= `docs/design/PET-MOVEMENT.md` §2.2.12；
- 口径：飞行期与拖动期**互斥**——我一起手拖动就由拖拽接管（US-26）。
- 口径（**落地口径 = 可见脚底**，B26 追加；源 = 用户 2026-09-18 原话「重力模式弹跳不真实，距离边框有一点的距离，我觉得应该完全等于边框」+ 批次档 `docs/batches/B26-pet-feel.md` §1.4 F2）：
  作为一个甩抛桌宠的用户，我想要她落地时**看得见的脚底**正好踩在工作区底边上，以便这次落地看起来是真的「踩实」而不是悬在地面上方一小段空气里。
  口径：物理地面**不再**以「窗口矩形下沿」为准，改按**可见身体底沿**补偿（补偿量 = 设计档常量 `FEET_INSET_DIP`）；散步段起点的纵坐标归位用**同一地面口径**（否则落地后的位置会被散步拉回未补偿区间）。
  边界（不做）：不改渲染层（`pet.html` / `pet.js` / `pet-preload.js` / `pet-chain*.js`）与几何层（`shell-pet-geometry.js`）——补偿只落在物理与散步的**地面取值**上；权威口径 = `docs/design/PET-MOVEMENT.md` §2.2.13。
- **修订（B27，2026-09-19；类别 = 口径扩展；源 = 台账 R21 用户实机「上左右的边界有点小了，下面的是足够的」）**：飞行边界的**上 / 左 / 右三面**由「窗口矩形」改为「**可见身体**」口径——四面 insets 单点常量（上 44 / 左 41 / 右 41 / 下 30 DIP；数值来源与机检等式见 `docs/design/PET-MOVEMENT.md` §2.2.14）；
  **散步边界同口径**（同一份补偿边界）；底面口径（`FEET_INSET_DIP` = 30）与起飞门 / 落地口径逐字不变。允许窗口透明留白越出工作区 ⇒ 对 B03「标称矩形 ⊆ 工作区」立**具名例外**（U-4 推荐 ①；候选与理由见同档 §2.2.14）。

### US-25 撞击形变反馈（Q 弹）（验收：`docs/design/PET-MOVEMENT.md` §3.1 AC4）

作为一个甩抛桌宠的用户，我想要她在**落地撞击**的瞬间有一个短促的「压扁—回弹」形变反馈（力度随冲击速度变化：轻落轻压、重砸重压），以便落地看起来是一次有重量的撞击，而不是瞬移到位。

- 边界（不做）：只做**落地**撞击的形变（碰壁 / 撞顶不做）；点击、喂食等既有互动不加挤压（点击已有既有开心动画，US-5 不回退）；
- 边界（不做）：形变**不写位置、不改窗口尺寸**——纯渲染面（变换落在一层包裹元素上，同时包住视频通道与 PNG 通道；不改 B18 链引擎）；
- 口径：系统声明「减少动态效果」时**不播放**挤压（承 US-19 的让步精神；样本同款取舍，见 `docs/design/PET-MOVEMENT.md` §2.1 F 组 / §2.2.7）。

### US-26 位移单写者仲裁（验收：`docs/design/PET-MOVEMENT.md` §3.1 AC5、AC6、AC7、AC15）

作为一个使用桌宠的用户，我想要她**任何时刻只被一个来源驱动位置**（我在拖她时她不会同时自己走、也不会一边飞一边走），以便三类位移不会互相打架（不出现抖跳、抢窗口或残留位移）。

- 口径（写权优先级，高 → 低）：**拖拽 > 物理 > 散步**；任一时刻至多一个持有**位置写权**（无人持有 = 只有离散停泊点可以写）；
- 口径（交接）：① 我一起手拖动 ⇒ 物理立即让出（**不写位置**，最迟 1 个 tick ≈ 16 ms）；② 正常松手 ⇒ 物理接管飞行直到静止；③ 松手时若既有的「贴边挣脱逃跑」分支已经接管（US-7 不回退）⇒ 物理**不介入**（既有彩蛋优先）；④ 物理在飞时不启动散步（散步请求被推后，待飞行结束后由既有守卫自行重排）；
  - **口径限定（本轮修正，2026-09-18；类别 = 口径收窄（非新增需求）；源 = 用户裁定「很慢的话就急停，很快的话就扔出去」）**：② 的「正常松手 ⇒ 物理接管飞行」以**释放速度 ≥ 阈值 `T`** 为条件（起飞门 = `docs/design/PET-MOVEMENT.md` §2.2.12）；**`v < T` ⇒ 物理不介入**（不起飞 = 今天的行为）；①③④ 与其余条目**逐字不变**。**物理关闭（默认）时本条逐字照旧。**
- 边界（不做）：**不改拖拽跟手的既有机制与手感**（8 ms 绝对定位、抓取偏移全程恒定）——她**不**改成阻尼弹簧跟手（那是本批明确不做项，见 §二）；
- 边界（不做）：不改散步 / 跑步的既有触发节奏（15–35 s / 相邻 4px 贴墙）与边界口径；
- 边界（不做）：仲裁层只管**窗口位置写权**——不管动画档位、工作状态与台词（动画侧优先级口径承 US-21，两套口径解耦，互不引用）。

### US-27 物理开关与默认值（验收：`docs/design/PET-MOVEMENT.md` §3.1 AC8）

作为一个不希望桌宠行为被改变的用户，我想要这个物理手感有一个明确、可切换的开关，并且它的默认值对我保守，以便我升级后看到的桌宠与今天一致——除非我自己打开它。

- 口径：开关 = 托盘「设置」子菜单中的 checkbox（与既有「任务完成时通知」同形），取值持久化在 `settings.json` 的顶层布尔键（设计档 §2.2.8）；
- 口径（**待用户裁定：批次档 §1.5 的 U-1**）：**默认值**由用户在评审 / 批准时裁定；设计档按**推荐 = 默认关**成文（依据：批次档 §1.4-5「默认行为保守」——本开关改的是用户可感知的松手后行为；裁定后只需改一处默认值与本行）；
- 口径：开关关闭 ⇒ 零采样、零飞行、零日志、零新增定时器；若关闭时正在飞 ⇒ 立即停泊收口（不留飞行态）。

### US-28 停下即停泊（含降级面）（验收：`docs/design/PET-MOVEMENT.md` §3.1 AC9、AC10）

作为一个使用桌宠的用户，我想要她在落地停下后**就停在看得见的地方**（不会停在屏外、不会尺寸失真、下次启动回到这里），并且在物理无法工作时**回退到今天的行为**（不报错、不卡住、不写坏她的位置），以便这个新功能不可能把我熟悉的桌宠弄坏。

- 口径：停泊 = **离散一次**的事件（可见性校正 / 骑线推离 → 尺寸校准 → 位置落盘 → 取证行），与既有停泊纪律同源（`docs/design/PET-MULTIMONITOR.md` §2.3.2 调用时机表口径）；**飞行过程中不落盘、不做尺寸写入**；
- 边界（不做）：飞行中不做位置钳制（校正只发生在停下的那一瞬）；
- 口径（降级，逐条）：物理关闭 / 轨迹不可估（温柔放下）/ 当前屏不可取 / 窗口不可用 / 被拖动抢先 / 显示器配置变化 / 进程退出 ⇒ 一律**回退到今天的行为**（关闭态 = 与今天逐位一致；其余情形 = 不起飞或就地停泊），并各留 1 行诊断（仅 `BIGFISH_PET_DEBUG=1`）。

### US-29 交互动作与个人动作分离（验收：`docs/design/PET-ANIMATION.md` §3.7 AC25、AC26）

作为一个与桌宠互动的用户，我想要**我亲手触发的动作**（点击 / 喂食 / 拖动她 / 把她拖到屏幕边界松手逃跑）与她**自己演示的动作**（没有人为干预时自己演的）分得清楚——我触发的动作一触即演、能打断她正在演的动作；她自己演的动作不会把我的反馈顶掉，以便我每次互动都得到明确回应，而她独处时始终是「自己在活动」的样子。

- 边界（不做）：不改既有 11 档语义与 PNG 通道口径；不改点击判定阈值（位移 > 5px）与左右键语义；不改自主小动作的触发源与节拍（1.5 min 节拍 / 40% 概率 / 2.4 s 时长照旧；其让位口径归 B26 面 = US-21）；
- 口径（分类，逐条）：**交互动作** = 点击（`happy`）/ 喂食（`eat`）/ **拖动中（`drag`，本批新增）** / **拖到屏幕边界松手逃跑（`escape`，本批新增）**；**个人动作** = 她自己演示的动作（自由链的待机 / 转向 / 分类动作）；**状态档**（入睡 `sleep` / 工作档 `work-*` / 位移档 `walk-*` 与 `run-*`）**不在这一二元内**，其规则照旧（本批不改）；
- 口径（优先级与打断）：交互动作 **>** 个人动作；交互动作**可以打断**个人动作（立即切换）；个人动作**不打断**交互动作（交互动作在途期间**不被个人动作 / 链的中途顶掉**——**不含**段末的衔接退场：段末前 `PET_OVERLAP_MS` 内的预触发换段属「链自主换段」的正常退场、非打断；起演仍恒立即，NFR-9 ≤ 300 ms 不变；口径依据 = `docs/design/PET-ANIMATION.md` §2.13.4）；
- 边界（不做）：**不做**「个人动作最小驻留时长」——不加「演完再切」的延迟响应（那会让点击失去即时反馈）；
- 口径（已知重叠，明示）：自主小动作（`read` / `starry` / `scared` / `happy`）与点击 / 喂食**复用同一批池键**；分类按**触发面**读，同一池键在两侧均合法（触发源本批不改）。
- **修订（B27，2026-09-19；类别 = 呈现变更；源 = 用户实机「她被拖到墙角的时候一直都是星星眼，而不太像逃跑动作」）**：`drag` 档的**呈现段**由「被鼠标拖拽悬空反馈」换为「被吓一跳」（被抓的惊吓表达；素材本体零改动、仅池引用一行——候选与理由见设计档 §2.14.7）；触发面分类与打断口径逐字不变。

### US-30 动作衔接丝滑（验收：`docs/design/PET-ANIMATION.md` §3.7 AC27、AC28）

作为一个盯着桌宠看的用户，我想要两段动作之间**不停一下再起**——上一段的收尾与下一段的起势**交叠**过去（而不是把上一段演到静止、下一段再从第一帧开始），以便她看起来是连续在动的，而不是一段一段「卡着播」。

- 口径（衔接方式）：链自主的段位切换在**上一段播完之前的一小段时间**就起下一段，两段短暂叠化；该提前量 = **单一可标定常量**（初始值 / 标定路径 / 到期条件见设计档 §2.13 的常量表）；
- 边界（**不得以牺牲「切换不出空白帧」换取**，承 US-16）：任何时刻上一段的画面都留在窗口里，直到下一段**真正可播**——衔接只允许改变换段的**时机**，不允许改变换段的**次序**（旧段退场仍晚于新段就绪）；
- 边界（不做）：**不用「把淡入时长拉长」作为解法**（淡入期间两段同时半透明，拉长只会让画面更久地「发虚」）；不引入后处理转场（模糊 / 位移 / 缩放）；不做按素材逐段标注「起势 / 收势」的对齐表；
- 口径（交互不受牵连）：用户触发的动作引起的切换**仍然立即发生**——不得为衔接增加交互响应延迟（承 US-29 与 NFR-9）；
- 口径（无障碍）：系统声明「减少动态效果」时叠化时长归零（瞬时切换，仍不出现空白帧）——US-19 口径不变。

### US-31 拖到屏幕边界的逃跑动作（验收：`docs/design/PET-ANIMATION.md` §3.7 AC29）

作为一个把她拖到屏幕边界的用户，我想要她**挣脱逃跑时演的是「逃跑」这件事本身、并且一次逃跑是连贯的一段**（不反复从头重来、不在逃跑途中闪出无关动作），以便这个既有彩蛋看起来是「她真的跑了」，而不是动作乱切。

- 口径（独立的逃跑动作档）：本批为逃跑设立**独立的动作档**（池键独立于普通跑步档），使「逃跑」在动作面与普通移动分开；
- 口径（不重播）：一次逃跑内对同一段的**重复到达不重播**（继续播当前段，不回到第一帧）；
- 边界（不做）：不改逃脱的**触发阈值**（距桌面外缘 4px）与**方向语义**（往反方向跑）——US-7 的触发面不回退（其动作呈现已按 US-7 的 B21 修订注记收窄）；
- 边界（不做）：不调整散步 / 位移的既有节奏与折返序列（15–35 s 起步 / 折返次数 / 段长参数照旧）；「素材段长（≈10 s）长于位移段长（0.25–2.9 s）」的固有张力**登记为观察项**，本批不解决；
- 口径：拖动中亦有对应交互动作（与 US-29 的 `drag` 同源，同为「用户手势 → 交互动作」）。
- **修订（B27，2026-09-19；类别 = 语义变更；源 = 用户实机「我没看出来她是逃跑的动作」）**：① escape 档由「持续循环（`loop=true`）」改为「**单遍播完再回链**」（≈ 段长 10 s，松手后逃跑姿态不再被腿末回 idle 切碎）；② R1 / R2 的作用域扩展到 escape 档（折返 / 同段重入不重启段、不回到第一帧）；③ 逃跑腿参数专用（更长更快，单一可标定常量）。触发阈值与方向语义不回退（US-7 修订注记照旧）。

### US-32 动作节奏「隔三岔五」（验收：`docs/design/PET-ANIMATION.md` §3.9 AC32、AC33）

作为一个长时间把桌宠放在桌面上的用户，我想要她在没有人为干预时**隔三岔五**才表演一个动作——每演完一个动作就回到一段安静的待机呼吸里休息一阵，再决定下一个动作，以便她看起来是「安静陪着我的活物」，而不是一直忙着切换动作。

- 口径（节奏机制，用户 2026-09-19 已裁 = ①+② 组合）：① **加权待机**——池权重把动作类占比从 ≈85% 降到 ≈40%（待机 ≈60%）；② **真·静默期**——链在 idle 档演完一个**动作类**段（`action` / `turn`）之后进入静默期：静默段（池键 `events.quiet`）循环播放、期间不换段，静默时长 = 单一可标定常量（默认 30 s，候选与理由见设计档 §2.14）；静默结束（或任何档位变化打断）后链重新掷骰。
- 边界（不做）：不改变**用户触发**动作的即时性（点击 / 喂食 / 拖动 / 逃跑照旧一触即演，NFR-9 ≤ 300 ms 不回退）；不改睡眠（2 min）、散步（15–35 s）、工作档（B19）的既有节奏与优先级；静默期不禁止任何用户交互与位移。
- 口径（静默形态，U-2 推荐）：静默期**保持「待机呼吸」段循环播放**（不是走 PNG 静态帧——那会带来 200↔140 的可见高度跳变，且观感是「死鱼」）；判据口径与候选否决见设计档 §2.14.3。

### US-33 逃跑与拖拽表达力（验收：`docs/design/PET-ANIMATION.md` §3.9 AC34）

作为一个把她拖到屏幕边界的用户，我想要她挣脱后的**逃跑看得出是逃跑**——跑得明显、逃跑的姿态保持完整一段再自然收尾，而且她被拖着的期间是「被抓」的惊吓样子而不是星星眼，以便这个既有彩蛋在观感上是一段完整的逃跑戏，而不是一闪而过的乱切。

- 口径（三件套，U-3 推荐）：① **逃跑腿参数专用**——逃跑腿更长更快（专用常量，单一可标定点）；② **逃生档播完整段再回**——escape 段由「持续循环」改为「单遍播完（≈10 s）再回链」；③ **拖拽期表达换段**——drag 槽改引用既有素材「被吓一跳」（替代「被鼠标拖拽悬空反馈」被用户读作星星眼）。
- 边界（不做）：不改逃脱的**触发阈值**（距桌面外缘 4px）与**方向语义**（往反方向跑）——US-7 的 B21 修订注记不回退；不新增 / 不修改任何素材本体（只改池引用与常量）；不改物理 / 位移写权。

### US-34 抛掷 / 散步活动范围按「可见身体」口径（验收：`docs/design/PET-MOVEMENT.md` §3.1 AC23、AC24）

作为一个甩抛桌宠的用户，我想要她飞行 / 弹跳的**活动边界按可见身体**贴到工作区边缘——上、左、右三面与底面同口径（身体边缘能真正碰到工作区边缘，而不是隔着窗口的透明留白提前停住），以便被甩到边缘时她看起来是真的撞到了屏幕边。

- 口径（四面 insets 单点常量）：飞行与散步共用同一份**四面补偿边界**（上 / 左 / 右 / 下 = 44 / 41 / 41 / 30 DIP；数值来源与等式见设计档 §2.2.14）；底面口径（`FEET_INSET_DIP` = 30）由 B26 落地口径**逐字不变**。
- 边界（不做）：不改窗口逻辑尺寸 250×270（US-11）；不改「飞行 / 散步不跨屏」（US-9 / US-24）；不改底面口径与落地等式；允许窗口透明留白越出工作区 ⇒ 对 B03「标称矩形 ⊆ 工作区」按 B26 O-14 先例立**具名例外**（四面；U-4 推荐 ①，候选与理由见设计档 §2.2.14）。

### US-35 等级曲线重定（验收：`docs/design/PET-AFFINITY.md` §3.2 AC-B31-1、AC-B31-2、AC-B31-7）

作为一个长期使用桌宠的用户，我想要好感度等级按一条明显拉长的曲线成长（**10 级不变**，一次长任务不直接满级、满级需要长期深度使用积累），以便等级成为有意义的陪伴进度，而不是一晚上就封顶的数字。

- 口径：阈值表 = 10 档**单一可调常量表**（`affinity-core.js`；完整对照与总量级理由见设计档 §2.2）——定标依据 = 用户实机数据（一次长任务 ≈127 万 token ⇒ 新 Lv.4；存量 3,545 点 ⇒ 新 Lv.5；满级 63,000 点 ≈ 25 次长任务）。
- 口径（**迁移**，U-3 推荐 ① 接受重映射，待用户批准时确认）：老数据不迁移、按新表直接重算等级（用户存量 Lv.10 → Lv.5）；「只对新积累生效 / 冻结补偿」两变体否决（理由见设计档 §2.5）。
- 边界（不做）：不改等级数（10 级）；不动 R16 等级门映射（B23 面按等级 1–10 键控，阈值数值不参与）；不动「点数只增不减」。

### US-36 喂食 = 有意义的加速路径（验收：`docs/design/PET-AFFINITY.md` §3.2 AC-B31-4）

作为一个喜欢喂她的用户，我想要喂食带来的好感点数与新的等级曲线量级匹配（一次零食在进度条上看得见），并且效率保持「喂食 = 被动积累 2 倍」的正确汇率，以便零食不再是数值上无感的安慰动作。

- 口径：食品点数 +400/+800/+1,200、价格 10/20/30💴、`EXCHANGE_RATE` = 10,000 token/💴（同调理由与候选对比见设计档 §2.3）；每💴 40 点 = 被动每💴（20 点）的 2 倍。
- 边界（不做）：不加新食品 / 新货币 / 新机制；不改「兑换走 wallet 不动 usage」的语义；不改兑换屋窗口结构（`openExchangeWindow` 面）。

### US-37 满级分支（验收：`docs/design/PET-AFFINITY.md` §3.2 AC-B31-3、AC-B31-5、AC-B31-8）

作为一个已经把她养到满级的用户，我想要满级后界面与播报收敛到一个干净的终态（点数显示 MAX 不再溢出增长、进度恒满、不再重复播好感增加），以便满级是荣誉终点而不是数字刷屏。

- 口径：满级 = level 10 ⇒ `maxed` 标记 · `pointsToNext` = `'MAX'` · `progress` = 1；点数播报改为**升级播报**（升一级播一次「好感满满，升到 Lv.x 啦~」，满级后自然无声）；显示面 = exchange `Lv.10 · MAX`、桌宠标签 `Lv.10 好感 MAX`。
- 边界（不做）：不改 10 级总数与 R16 映射；不做满级后新玩法（转生 / 奖励）；点数内部仍真实累积（收敛的是显示与播报面）。

### US-38 时节门——节日动作按日历窗口解锁（验收：`docs/design/PET-UNLOCK.md` §4 AC-B23-1）

作为一个把鲸鱼娘当节日陪伴的用户，我希望在某个节日 / 节气的**窗口期**里（落地口径 = 节前 6 天 + 节日当天 + 节后 3 天 = **10 天**，用户 2026-09-20 裁定，见下方口径行），她会做对应的时节动作（中秋赏月吃月饼、端午吃粽子、春节写福字收红包……），而**其余时间这些动作锁死绝不出现**——节日的稀缺感才成立。

- 口径：系统日期（**本机系统时间**，零网络校时）落入某节日条目的 `[节前 6 天, 节后 3 天]` 闭区间（**含节日当天共 10 天**：节前 6 + 节日当天 + 节后 3；端点逐日列举见设计档 §2.5.2）⇒ 该条目关联的时节动作解锁；判定为**纯函数**（输入 = {now, rules}）。**所有**时节动作默认锁；时节门**关闭** = 该门来源不做过滤（时节动作全解锁，**不是**全锁——评审 #1 口径；D-2：时节动作**只按日期锁、不按等级锁**）。
- **天数口径差额（S-4 订正；用户 2026-09-20 已裁——差额消解）**：批次档 §1.2 用户原话「前一周到后三天」的字面读法 = 11 天（节前 7 + 当天 + 节后 3），与 D-2「一年只有 10 天」相抵；
  **用户 2026-09-20 15:02 裁定「可以的，差不多都行，10天也行」⇒ 落地口径 = 10 天**（节前 6 + 节日当天 + 节后 3）——与已落地数据档、AC-B23-1 钉死端点
  （中秋 2026：09-19 / 09-28 为窗内沿点、09-18 / 09-29 为窗外沿点）三者一致，零实现改动；「取 11 天」变体（数据档 21 节日 × 10 年窗口逐条重生成 + AC 端点重钉）**已随裁定作废**。
- **跨年窗口合法（S-3 订正）**：窗口校验只拒**倒置**（起点 > 终点）；农历节日窗口可自年末伸入次年初（数据档实证：腊八节 `2028` = `2027-12-29…2028-01-07`、`2031` = `2030-12-26…2031-01-04`）；判定 = 按该条目**全部年份键**取包含（设计档 §2.5.2）。
- 数据面：2026–2035 **离线节日表**（固定公历 + 农历 + 节气逐年成表，约 40 行，零依赖零算法；D-1 用户裁定）；表内每条含**可读中文条件串**（US-43 图鉴复用）；**到期条件显式**——覆盖至 2035-12-31，过期须出新表（禁永久先例）。
- 边界（不做）：不做天文 / 农历算法库；不做网络校时 / 时区服务；不改 `assets/pet-anim/pool.json`（门控数据独立成档）；素材本体只读。

### US-39 饭点门——三餐动作按时刻解锁、一天一次、过点不补（验收：`docs/design/PET-UNLOCK.md` §4 AC-B23-2）

作为一个在饭点想看她吃饭的用户，我希望系统时刻落在三餐窗口内时「吃早餐 / 吃午餐 / 吃晚餐」解锁，**同一饭点演过一次就不再出现**，过了饭点也不再补——像真的按三餐过日子。

- 口径：三餐窗口 = **早餐 06:30–09:30 / 午餐 11:00–13:30 / 晚餐 17:00–20:00**（U-1 推荐值 ①，待用户批准时确认）；窗口内对应饭点动作解锁；**一天一次** = 同一自然日同一饭点演过后即从可选集排除（演过记录落 `userData` 持久化）；**过点不补** = 窗口外不解锁、不追演。
- 边界（不做）：不做补演 / 补卡机制；不做跨日合并（自然日以本机时钟 00:00 分界）；不改 B18 池权重面。

### US-40 等级门——好感等级解锁动作、Lv.1 不单调（验收：`docs/design/PET-UNLOCK.md` §4 AC-B23-3、AC-B23-4）

作为一个陪伴时间越来越长的用户，我希望好感等级提升会**解锁新动作**（10 级对 10 档映射），让「她越来越丰富」看得见、有获得感；同时新用户（Lv.1）就有一套足够丰富的日常动作，不因等级门而觉得单调。

- 口径：动作解锁级 ⇔ 好感等级 ≥ 该动作的解锁级（等级 = 既有 `levelForPoints` 输出，**映射挂级数、不挂 token 刻度**）；映射 = 批次档 §1.5 D-3 表（用户 2026-09-18 确认）落成可机检权威数据表，
  **每条动作恰好属于一级**（无遗漏、无重复覆盖，机检——**覆盖谓词 = 等级门域段名并集 = categories 段 − 时节 21 段 − 饭点 3 段（逐段恰一次）**，复核轮 2 #1 补）；
  Lv.1 可选集 ≥ **10 段**且含 ≥1 段「惊喜段」（硬约束 6，机检）——**本批落名：惊喜段 = 「照镜子」，即这 10 段之一**（复核轮 2 #2 定名；「小幅度原地360度旋转展示」属 Lv.2 普通段，不作惊喜段）。
- 边界（不做）：不做等级回退（等级只升不降，随既有好感面）；不动 `affinity-core.js` 阈值表与喂食面（B31 契约）；时节动作不参与等级门（D-2）。

### US-41 可选集硬排除与三把锁开关（验收：`docs/design/PET-UNLOCK.md` §4 AC-B23-5、AC-B23-6）

作为对默认行为敏感的用户，我希望**锁住的段绝不入选**（是硬排除而不是把权重调成 0——调零仍可能被抽中），并且三把锁**各自可关、默认全开（直接启用解锁玩法——用户 2026-09-20 裁定）**；全关时她的动作池回到无门控形态（与今天逐位一致——**除 US-39「一天一次」状态面外逐位一致**，复核轮 2 #3）。

- 口径：可选集计算 = 纯函数 `eligible(pool, {now, level}) → 可入选段集合`，喂给既有选段链；机检面 = 运行期日志 `pick=` 行中**锁定段名零出现**（硬约束 3）；
  开关三枚（时节 / 饭点 / 等级）入设置默认表，**默认值 = 开（用户 2026-09-20 裁定——装完即进入解锁玩法）**；任一门**关闭** = 该门来源不做过滤（等级门关 ⇒ 全池按已解锁处理，U-5 ①「可关即全解锁」——三门同口径）；
  **两层口径**：`allowSet` = 段名集合面（随开关走；全关 ⇒ 全池）；「当日已演排除」= 状态面（**不随开关走**——一天一次是 US-39 本体语义，复核轮 2 #3）。
- 边界（不做）：不做按锁粒度的独立提示；不改既有选段优先级（B21 交互 / 个人分离、B27 静默期逐字保留）；不改 B18 池校验 V1–V6。

### US-42 解锁提示——新动作可看破的一次播报（验收：`docs/design/PET-UNLOCK.md` §4 AC-B23-7）

作为一个想第一时间知道「她学会了新动作」的用户，我希望等级提升或节日窗口开启带来**新解锁**时，给一次**可见的提示**（托盘通知 + 桌宠一句台词），好让我去图鉴里看新东西。

- 边界（不做）：不做专用庆祝动作（U-2 ②否决，理由见设计档 §2.6）；不做纯日志静默方案（U-2 ③否决：提示是本条需求本体）；不做解锁历史列表页。

  - **修订（B35，2026-09-20；类别 = 呈现升级；源 = 用户原话「动作图签做的太烂」+ 裁定 D-1）**：本条「不显示缩略图（纯文字）」自 B35 起**作废**——图鉴面升级为**视频卡片墙**（US-46：每动作一张卡、直接播放对应 webm）；「显名 + 灰化」「按分类分组」「条件可读化」「百分比口径 = 可解锁分母（categories 80 段）」四条口径**逐字保留**（卡 = 行的呈现升级，数据面与门控同源不变）。权威口径 = `docs/design/PET-GALLERY.md` §2.3。

### US-44 弹窗可调整大小与尺寸持久化（验收：`docs/design/PET-GALLERY.md` §4 AC-B35-1、AC-B35-2）

作为一个想收集她全部动作的用户，我希望图鉴的每个动作是一张**精美的标签卡**——卡片直接播放该动作的 webm（**可见即播 / 离屏即停 / 懒加载**），带动作名、解锁条件、状态徽标（已解锁 / 未解锁 / 喜欢 / 已屏蔽 / 常驻 / 事件 / 特权），顶部有**收集进度**，以便翻图鉴像翻卡册。

### US-47 喜欢体系（验收：`docs/design/PET-GALLERY.md` §4 AC-B35-5）

作为一个有偏好的用户，我希望在图鉴里给动作**打星收藏**——她自主表演时喜欢的动作**更常出现**、收藏的卡片**置顶成组**、还能开「**只看喜欢**」让她只演我喜欢的组合，以便她的日常演出都是我的菜。

- 口径：喜欢面 = **categories 80 段**（独占事件唯一段与基础 / 事件档不可喜欢——UI 无星标）；权重提升 = 链的**类内选段加权 ×3**（段级倍率、单一常量 `PET_FAV_WEIGHT`，不落 `pool.json`；分类间权重不变）；「只看喜欢」= **合取**（喜欢 ∧ eligible 已解锁——不越锁，锁着的喜欢段仍不入选）；同一开关双面生效（链面过滤 + 卡墙显示过滤），**默认关**。
- 边界（不做）：事件档内轮换（`nextInSlot`）不加权；不做多收藏夹 / 组合命名；不做喜欢度分级（只有 0/1 星标）。

### US-48 屏蔽体系（验收：`docs/design/PET-GALLERY.md` §4 AC-B35-6、AC-B35-7、AC-B35-8）

作为一个不想看到某些动作的用户，我希望在图鉴里**屏蔽**动作——被屏蔽的段在**随机轮换池与事件触发**（喂食联动 / 点击回应等交叉引用面）里都**绝不再出现**，以便桌面观感由我把关。

- 口径：屏蔽 = **硬排除**（承 B23 口径：运行期 `pick=` 日志零出现，**不是**权重调零）；**独占事件唯一段不可屏蔽**（`events.drag` = 被吓一跳 / `events.escape` = 原地左转奔跑 / `events.quiet` = 待机呼吸休闲——UI 标「事件独占·不可屏蔽」）；某事件候选被全屏蔽 ⇒ 该次触发在动画面**忽略**（保持当前段 + debug 日志一行，显式回落不黑屏）；屏蔽中的段**正在播放** ⇒ 演完本段（循环段收尾本遍）后不再出现（温和切换）；喜欢与屏蔽**互斥**（后置操作覆盖前置，归一化由校验谓词承载）。
- 边界（不做）：不做屏蔽分组 / 定时解除 / 屏蔽理由；基础档与事件独占段不在屏蔽面（常驻语义）；屏蔽不切断当前播放（温和切换，US-48 口径句）。

### US-49 Lv.10 特权——无视时间限制（验收：`docs/design/PET-GALLERY.md` §4 AC-B35-9）

作为一个把她养到满级的用户，我希望 **10 级后**节日与三餐动作**无视时间限制**——时节窗口、饭点窗口、「一天一次」三者全部解除，节日吃饭动作随时可演、可入喜欢组合，以便满级是真正的自由。

- 口径：谓词 = **level ≥ 10 ∧ 特权开关开**（设置键 `petUnlockLv10`，**默认开**、托盘设置子菜单可关——与三锁开关同面；关 ⇒ 回到 B23 语义）；特权只解除三类**时间**限制，**不**解除用户屏蔽（屏蔽优先于特权）与规则档坏档回落；**Lv.1–Lv.9 的门控语义与 B23 交付态逐位一致**（桩测断言面 = B23 用例全量复跑）；图鉴卡对特权放行的时节 / 饭点段显示「特权」徽标。
- 边界（不做）：不动 Lv.1–Lv.9 任何门控语义；不给 Lv.10 加新动作 / 新素材 / 新数值；不做特权等级细分（只有 ≥10 一档）。
- **修订（B35 微修②，2026-09-20；类别 = 呈现面；源 = 用户实机裁定「我才六级，托盘不应该看到这些东西」）**：托盘「满级特权 · 无视时间限制」项**未满级不显示**（满级后出现；开关值与「默认开」语义不变）；显隐刷新 = 等级跨档触发托盘菜单重建 + 启动 `loadAffinity` 后重建一次。

### US-50 偏好与窗口尺寸持久化（验收：`docs/design/PET-GALLERY.md` §4 AC-B35-10）

作为一个不想重来的用户，我希望我的**喜欢 / 屏蔽集合**与**窗口尺寸**在重启后都在，以便我的布置不丢。

- 口径：喜欢 / 屏蔽集合存 **`userData/pet-prefs.json`**（独立档，先例 = `unlock-state.json`；损坏按「首次使用」重置，不崩）；窗口尺寸存 `settings.json`（`petExchangeSize`）；「只看喜欢」与「Lv.10 特权」两开关入 settings 默认表（与 `petUnlock*` 三开关同面）；写盘 = **事件驱动**（toggle / resize 停手时），不轮询、不入任何 tick 路径。

## 四、非功能标准

### NFR-1 性能（跟手度与开销；验收：AC1、AC9）

- **推导方式**：窗口位置必须由「光标当前位置」直接推导（绝对定位），推导周期 ≤ 8ms（约 125Hz），且单次推导内不得包含同步的窗口尺寸查询。
- **跟手判据**：拖动过程中，「光标」与「鲸鱼娘被抓住的那一点」之间的相对偏移恒 ≤ 2px；需覆盖慢拖、快拖、大幅甩动三种情况。
- **开销判据**：拖动期间主进程 CPU 增幅 < 5%。度量方式：`process.getCPUUsage()`（Electron 主进程 API，见 `node_modules/electron/electron.d.ts:24153`）；基线取拖动前 10s 空闲均值，采样为连续拖动 10s 的均值。
- **空闲判据**：光标不动时，拖动循环不得产生窗口位置写入（同目标位置去重）。
- **写入纪律（B03 补充，2026-09-16；源 = `docs/design/PET-MULTIMONITOR.md` §2.2「E6 的实证收口」）**：
  - 拖动期间的**尺寸写入**至多发生一次 / 每个跨屏事件，且仅在「**窗口标称矩形完全进入新屏 `bounds` 的首个 tick**」（该 tick 即写入时点；骑线期不触发）时；**同屏内拖动全程零尺寸写入、零窗口尺寸查询**（「零窗口尺寸查询」半句限**判定路径**；debug 日志行除外——判别面见本条末的机检判据）（每 8 tick 的尺寸断言已废止）。触发判据与写入时点口径 = `docs/design/PET-MULTIMONITOR.md` §2.3.3。
  - 该**触发判据**为**纯算术**（缓存屏矩形比较 + 中心点常量偏移），**判定本身零 API 调用**；跨屏事件另有 **+1 次 `getSize()`**（该次校准内的读回）——仍在离散事件上、不入每 tick 推导路径（成本口径 = `docs/design/PET-MULTIMONITOR.md` §2.6 NFR-1 行）。
  - 松手时的**位置**写入至多一次（可见性校正与骑线推离合并为同一次写入）。
  - **口径限定（B20，2026-09-18；类别 = 澄清，非语义变更）**：上一子条限**松手事件内**；松手之后的**物理接管期**（= 物理开启且释放速度 ≥ 阈值 `T` 时的飞行期，起飞门 = `docs/design/PET-MOVEMENT.md` §2.2.12）改按 **NFR-18** 判（每 tick 至多一次 + 同目标去重），且飞行期**零落盘、零尺寸写入**；**`v < T`（缓放 / 正常放下）时本子条逐字照旧**（松手仍只一次位置写入）。**物理关闭（默认）时本子条逐字照旧。**
  - 机检判据 = `docs/design/PET-MULTIMONITOR.md` §3.1「拖动期写入纪律的机检判据（丝滑性）」S1–S7（日志面）**＋** §3.3 静态核对第 4 项（**符号级**：「`BIGFISH_PET_DEBUG` 关闭时，拖动 tick 的**判定路径**内无 `getSize()` 调用；debug 日志行按 §3.3 的取证需求可有」——“零窗口尺寸查询”半句的判别面，查询在日志面不可见）；日志面 = `userData/pet-geometry.log`（`BIGFISH_PET_DEBUG=1`）。

### NFR-2 可用性（停止与状态清空；验收：AC3）

- 松手后 ≤ 200ms 内窗口必须静止。
- 拖动状态在所有路径下都必须被清空，最迟 ≤ 2s——包括事件丢失、渲染进程异常、窗口销毁等异常路径。
- 度量方式：诊断日志（格式见设计档 §3.3）中 `drag-end` 行之后不得再出现位置写入行；异常路径下 `drag-end` 行的 `reason` 必须取兜底值。
- **修订（B20，2026-09-18；类别 = 语义变更；待用户追认 = U-7；源 = `docs/batches/B20-pet-physics.md` §1.2）**：本条「松手后 ≤ 200ms 内窗口必须静止」自 B20 起限定为「**拖动循环**在松手后 ≤ 200ms 内不再写入位置」；**物理开启且释放速度 ≥ 阈值 `T`**（起飞门 = `docs/design/PET-MOVEMENT.md` §2.2.12）时的**收口判据** = **NFR-19**（近地软着陆档 ≤ 4 s；其余档 ≤ 5 s 且收口在地面）。
  - **收窄（本轮修正，2026-09-18；源 = 用户裁定「很慢的话就急停，很快的话就扔出去」）**：**释放速度 < `T`（缓放）时本条逐字照旧**——松手后 ≤ 200ms 内静止，物理面零写入（诊断行 `phys-stop reason=below-threshold`）。
  - 度量方式同批收窄：「`drag-end` 行之后不得再出现位置写入行」→「**拖动循环的 `tick` 行**在 `drag-end` 之后绝迹」（物理接管期的写入由 `phys-*` 行承载，见 `docs/design/PET-MOVEMENT.md` §2.2.11）。

### NFR-19 静止收口与有界（验收：`docs/design/PET-MOVEMENT.md` §3.1 AC11）

- **必然收口（主判据）**：从任意可达初速（`|v| ≤ 3600 × throwPower`）与任意屏内起点出发，飞行在 **≤ 5 s**（= 硬上界 `PHYS_MAX_FLIGHT_MS`）内**收口**（= 停机 → 停泊序列）；**收口一律落在地面**（`y == maxY` + 速度归零）——**任何情形不得停在半空**；
- **≤ 4 s 静止（限定档）**：**仅对近地软着陆档成立**——判据 = **首触竖直速度 `|vy_imp| ≤ 800 px/s`** ⇒ 起抛后 **≤ 4 s** 内 `atRest`（`e = 0.55` 实测档内最坏 3.33 s；分界 ≈ 1000 px/s）。一阶模型 = 竖直反弹链 ≈ `(2·|vy_imp|/g)·Σ_{k=1..K} e^k`（截断级数：`K = max{k : e^k·|vy_imp| ≥ REST_VY}`）+ 首段下落 ≤ `|vy_imp|/g` + 接地摩擦尾 ≈ `ln(|vx|/REST_VX)/groundFriction`；
- **只停一次**：`atRest` 一旦为真，物理状态即清空、循环即停止（不得复飞、不得抖动重启）；
- **硬上界**：另设 5 s 兜底上界——到点 ⇒ **强制落地收口**（收到地面 + 速度归零 + 再走停泊序列）+ 1 行诊断；任何参数组合下状态都必须清空（承 NFR-4 的「异常路径也清空」）；
- **界内**：飞行轨迹恒在起飞时确定的工作区区间内（`x ∈ [minX, maxX]`、`y ∈ [minY, maxY]`）——**收口点必在区间内**（不依赖起飞点：US-2 允许拖出屏、B03 只保中心点可见 ⇒ 起飞时按设计档 §2.2.5 归一化钳入）；
- 度量方式：开发期桩测**扫描**（8 方向 × 4 速 × 4 起点）**分两支**断言——① 档内（`|vy_imp| ≤ 800 px/s`）≤ 4 s `atRest`；② 全体 ≤ 5 s 收口且**收口在地面**；③ 轨迹不出界。现行参数下的重算基准 = **≤4 s 74 例 · 4–5 s 44 例 · 走 5 s 上界 10 例**（128 例扫描集；明细见 `docs/batches/B20-pet-physics.md` §2.12）。本条数值为**设计期给定值**（同 NFR-9 / NFR-14 口径），首轮实测后可回调——回调属需求层判定，设计档不单方面放宽。
- **参数前提（2026-09-18 补）**：本条两支判据的数值**随 `restitution` 变**——现行值 = **本仓调 0.55**（用户 2026-09-18 裁定 B；理由与重算数据 = `docs/batches/B20-pet-physics.md` §2.12，差异登记 = `docs/design/PET-MOVEMENT.md` §2.5.3 O-12）；该常量单点、可调，改值须同源重算本条两支判据。
