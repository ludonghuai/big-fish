### 1.4 主 agent 的技术裁定

- **R1 批次归属**：本批为**新批次 B07**。依据：B06 的设计评审与用户批准只覆盖 B06 范围（启动形态 / 托盘 / 拆分 / 门禁）；token URL 契约、`--no-open`、探测机制重写均为**新语义**，须走完整链（需求 → 设计 → 评审 → 批准 → 实施）。不并入 B06 修正轮。
- **R2 主窗口 URL 修法基线（可审，供 eng-designer 采纳或改判）**：主窗口 URL = 后端启动输出行 `dsh web: <url>` 的地址（含 `?token=`，回环主机 + 当前端口校验）；`waitForReady` 通过后留一段宽限等待该行；未捕获时回落裸地址 `http://127.0.0.1:<port>` 并记日志。
- **R2 被否决备选**（依据 = §1.6 #4）：① **关闭鉴权**——harness 无此开关；② **自行推算 token**——`BrowserAuth.launchToken` 为进程内随机（`dsh-client-connection/lib/index.js:222-244`），进程外不可读。
- **R3 取证面不回退（硬）**：后端 stdout/stderr 由「直写日志文件」改管道时**必须双写 `bigfish.log`**——B04 / B05 的验收取证面（`harness activate …` / `harness install phase=…`）依赖该档。
- **R4 通知机制基线（可审，立案后经一次改判）**：Windows 走 `fs.watch(recursive)` 主路径，其余平台走异步扫描回落；**busy 判定面 = 路径任一段落 ∈ {`profiles`, `node_modules`} 即忽略（＝旧实现 skip 语义原样）**。口径说明：本裁定原写「按顶层段过滤」并以「当前布局下与旧语义等价」为据；eng-designer 复核后按**任一段落**落笔（对旧语义逐字忠实，且使 watch 与回落两路共用同一谓词），主 agent **采纳**其改判（见 §1.9）。等价性证据 = §1.6 #8。
- **R5 明确出批（本批不做）**：harness bundle 升级（T10，顺延 B08）· 桌宠多屏实机验收（T9）· 首次发版演练与安装包托管（T8 / T11）· 自动化测试基建（T4）· `market.js` 拆分（500 行贴线未超）。
- **R6 收口写权**：requirements / design 两档由 eng-designer 写（含修订）；批次档 §5 由 eng-coder 写；§1 / §4 / §6 与台账由主 agent 写。
