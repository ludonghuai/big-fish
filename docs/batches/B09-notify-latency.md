# B09 —— 任务完成提醒的及时性

> 六段制批次档（每段一位作者、append-only）：§1 主 agent · §2 eng-designer · §3 评审子代理 · §4 主 agent · §5 eng-coder · §6 主 agent。

## §1 批次立案（主 agent）

### 1.1 立案背景

「Bigfish 任务已完成」提醒**迟滞太久**：用户体感为「早就做完了结果才发消息」。机制（主 agent 读码核实）：

- 判据 = **末次写入后空闲 `IDLE_NOTIFY_MS`**（`main.js:49` `30 * 1000`）⇒ 提醒时刻 = 末次写入 + 30 s（另有 5 s 周期定时器，实测落在 30–35 s）；
- 忙信号 = `~/.dsh` 下**非** `profiles/` · `node_modules` 的写入（`shell-notify.js` `isIgnoredPath`）——**与「真实完成」无因果**，只是「最近有没有磁盘活动」。

⇒ 提醒时刻与真实完成时刻**脱钩**，且固定多出 30 s。

### 1.2 任务来源

- 用户 2026-09-17 真机验收原话：「**通知间隔的时间太长了，早就做完了结果才发消息**」。
- 台账需求池 **R10**（本批承载）。
- **注意**：B07 的需求条目 US-11 明文锁定「通知文案 / 阈值（`IDLE_NOTIFY_MS = 30 s`）/ 托盘开关语义**不改**」⇒ 本项属**新需求点**，本批为独立批次，不改 B07 已核销的任何判据。

### 2.3 判定规则（判据句，逐字；实施按此执行）

> 静默达 `IDLE_NOTIFY_MS` 后，判定**一次性**执行（异步）：
> ① 取 `<dshHome>/sessions/**` 下 mtime 最大的会话日志 `L` 与 `<dshHome>/storages/session_projcache/sessions/*.json` 下 mtime 最大的记录 `C`；
> ② `C` 缺失 / 不可解析 / 无 `record.rows.turnBoundary` / `rows.turnBoundary.ver !== 2` ⇒ **降级**（阈值改用 `IDLE_NOTIFY_FALLBACK_MS` = 30 s = 现状语义）；
> ③ `mtime(C) + 1000 ms < mtime(L)` ⇒ **本轮不提醒**（快照落后于会话日志）；
> ④ `rows.turnBoundary.val.openTurnStartSeq !== null` ⇒ **回合在途 ⇒ 不提醒**；
> ⑤ 否则 ⇒ **通知一次**（既有通知语句逐字保留）。

- **误报边界（本批核心判据）**：设计者实测（本机真实会话事件日志，解 zstd 帧取事件时间戳）单次 `tool/call → tool/result` 静默
  **21.9 s**、其间 `~/.dsh` 零写入 ⇒ **只缩阈值必然误报**（30 s 阈值下 >30 s 的工具调用 / 构建同样误报）；故完成判据必须带 Harness 自己落盘的
  `turn/end` 标记——该档**每个 `turn/end` 立即无条件落盘**（`@deepseek-ai/dsh-session-projection-cache/lib/index.js:290-321`；写入阈值 `writeEveryEvents=200` / `writeIntervalMs=5000`，源 = `@deepseek-ai/dsh-base/cordis.patch.yml`）。
- **承重前提**：`IDLE_NOTIFY_MS`(8000) **必须大于** `writeIntervalMs`(5000)——否则判定会读到尚未折叠最近事件的快照；前提失效 ⇒ 规则③ 兜底（方向 = 抑制）+ 规则④ 静态判据把门（设计档 §2.2.12）。
- **执行面**：判定仅在「静默 ≥ 阈值且本轮未通知」时触发，结果按 `lastBusyAt` 记忆（每静默窗至多一次读，任何写入自动失效重判）；异步 + 防重叠，5 s 回调内无同步 I/O（NFR-5 判据不变）。
