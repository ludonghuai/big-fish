## §1 立案（主 agent）

### 1.1 目标（一句话）

给桌宠装上**物理手感**：拖拽跟手具备阻尼弹簧质感、松手后按重力抛物落地并**碰壁 / 触地反弹**、落地受摩擦逐渐停下、撞击瞬间有 **Q 弹挤压**——且**不破坏**既有拖拽跟手与几何纪律。

### 1.2 范围（做 / 不做）

**做**：
- **物理量参数化**（承样本规格）：`gravity` / `restitution` / `groundFriction` / `ceilingBounce` / `throwPower`（弹簧系数 K/C + 甩抛初速与软上限）。
- **甩抛与落地**：松手速度 → 抛物线 → 碰壁 / 触地反弹 → 摩擦衰减 → 静止（回到既有停泊纪律）。
- **Q 弹挤压**：撞击瞬间的形变反馈（渲染面，不写位置）。
- **位移仲裁层**（**本批核心**，承 O10）：把既有三个位移来源（**拖拽** / **散步** / **物理**）收进**单写者**仲裁——明确优先级、互斥与交接（含 O10 的「链是否需要接管位移」的落点判定）。
- **开关与默认值**：物理面可关（默认值待裁定，见 1.5）。

**不做（本批出批）**：
- 多实例 / pet pack（E 面）· 余额/碎碎念/对话（D2 面）· 素材生成链（C 面）· 工作状态联动（D1 面，B19 独立批）。
- **不改**：`shell-pet-geometry.js` / `shell-pet-drag.js`（**几何冻结面**，硬门禁）· `assets/**` 素材本体 · `pet-chain-core.js` / `pet-chain.js`（B18 链引擎）· B03 的停泊/尺寸纪律与 13 轮修正结论。

### 1.4 硬约束（不得偏离）

1. **几何冻结**：`shell-pet-geometry.js` / `shell-pet-drag.js` **不得出现在 `git diff`**（硬门禁；承 B18 同款）。
2. **位移仲裁必须显式成文**：新物理写者与既有两写者的**优先级 / 互斥 / 交接**必须逐条落档（含「谁在什么时刻拥有位置写权」的状态机），并**证明不与几何档的「离散停泊」纪律相抵**——若物理需要在 tick 内写位置，必须由仲裁层**独占该写权**且几何校正仍在离散点发生。
3. **既有手感零回退**：拖拽跟手的既有观感（B03 调定）不得变差；物理只在**松手后**接管（拖拽中仍按既有 8 ms 跟手）。
4. **零新依赖**：不引入 npm 包（自写积分/碰撞）；不改 `dependencies`；新增渲染档须同步 `build.files`。
5. **默认行为保守**：物理对手感的影响是**用户可感知变更** ⇒ 默认值须显式裁定（见 1.5 U-1）。
6. **行宽 ≤300（不含行尾 CR）· 代码档 ≤500 行 · 文件头标准形**。
7. **许可面沿用 B18**：代码 MIT 须署名（已在位，不得改写）；素材禁商用。
