# B24 批次档 —— 动作导入：用户给一段视频，自动解析成桌宠动作

> 六段制 · append-only · 一段一作者：§1 主 agent / §2 eng-designer / §3 设计评审 / §4 主 agent / §5 eng-coder / §6 主 agent。
> 本档 = **本仓原创需求**（**非**移植面；样本的同类能力是**开发者脚本**，本批做的是**用户面入口**）——台账 **R18**。
> 用户 2026-09-18 原话：「可以加，**给用户一个入口添加视频之后，是不是可以解析成动作呀？？？**」

## §1 立案（主 agent）

### 1.1 目标（一句话）

给用户一个**极简入口**：丢一段视频进来 ⇒ 自动**归一化 + 校验 + 生成池条目** ⇒ 桌宠多一个**真正属于用户的动作**。

### 1.2 范围（做 / 不做）

**做**：
- **导入入口**（托盘菜单项 / 设置面板二选一，落点由设计者判定）：选文件 ⇒ 导入。
- **产物归一化**：转成我们已锁定的素材规格（见 1.3 规格表）——尺寸缩放 / 画布居中 / 安全区适配 / 时长与体积上界。
- **透明面处理**（两档，见 1.5 U-1）：① 绿幕源 ⇒ 自动抠像 ② 已带透明 ⇒ 直通。
- **alpha 校验**：产物必须真带 alpha（否则会在桌面上出现"黑底方块"✗）——校验失败给**可读的失败原因**，不静默降级。
- **自动生成池条目**：写入**用户池**（名字来自文件名，组 = 「自定义」，权重/等级用保守默认），**不改动**随包池 `assets/pet-anim/pool.json`。
- **预览/试播**：导入前或导入后可试播一次（用户要能立刻看到效果）。
- **管理**：列出已导入动作 + 删除（删除 = 只删用户池条目与用户素材，**不碰随包素材**）。

**不做（本批出批）**：
- **不做视频生成**（不接 AI 生成模型 ✗）——用户提供源视频。
- 不做云端素材市场 / 分享 / 下载 ✗；不做多宠物与 pet pack（**E 面**）✗。
- **不改**：`assets/pet-anim/webm/**`（随包素材只读）· `shell-pet-geometry.js` / `shell-pet-drag.js`（几何冻结面）· B18 的池校验 V1–V6 与双缓冲形态 · B19 / B20 / B21 / B23 各批契约。

### 1.3 现状实测（勘察，2026-09-18）

| 面 | 实测事实 | 证据 |
|---|---|---|
| **我方入库面（现成）** | 加一个动作 = **2 步**：① 把 `X.webm` 放进 `assets/pet-anim/webm/` ② 在 `pool.json` 对应组加名字 `"X"`（**动作名即文件名**）⇒ **零代码** | `assets/pet-anim/pool.json`（结构键 = `version / canvas / body / dir / ext / weights / idle / turn / moves / categories / events`）· `docs/design/PET-ANIMATION.md`（B18 段池契约） |

| **样本的同类能力（开发者脚本，可借鉴）** | `samples/dsh-pet/scripts/`：`chroma_step02.py`（HSV 色相抠像 · **统一使用工作区自带 ffmpeg、零第三方依赖**）· `normalize_step03.py`（跨段统一角色大小）· `encode_thumbs.py` / `encode_preview_gifs.py`（缩略图 / GIF 预览）· `check_alpha.py`（**校验 alpha 通道真实存在**）· `watermark_step01.py` + `make_mask_black.py` + `fill_nn.py`（去 AI 水印）· `pr_import_step02.py`（手抠 MOV 导入）· `encode_hevc_alpha.sh` + `hevc_alpha_encoder.swift`（macOS HEVC-alpha） | 主 agent 亲扫（10 档 / 逐档首行与注释） |
| **样本的源素材规格（提示词层）** | `prompts/桌面宠物 10 秒动作提示词.md`（102 KB / **108 个标题** / 通用前缀强制：16:9 · 纯绿幕 `#00FF00` 无色差 · 人物头顶 20% / 脚底 85% · 四周 10% 安全边 · **禁止 X/Y 平移**（只许原地轴心转/跳）· 道具「无→有→无」闭环 · **第 10 秒必须完全恢复第一帧姿态**） | 同上（主 agent 亲读通用前缀 22 行） |
| **⚠️ 关键成本点（可行性核心）** | **浏览器自带能力编不出"带 alpha 的视频"**：`MediaRecorder` 与 `WebCodecs` 的 VP9 **均不暴露 alpha 通道** ⇒ 纯前端路子走不通；要自动化必须引入 **ffmpeg 系**（wasm 或原生二进制）⇒ 本批**触碰「零新依赖」硬约束**（须用户裁定，见 1.5 U-2） | 技术判定（主 agent）；样本自身即"自带 ffmpeg"（其脚本注释明写） |
| **用户素材的落点（重要）** | 用户导入的素材 = **用户自有内容** ⇒ 必须落 `<userData>/`（**不进仓、不入 `build.files`**），与随包素材物理分离；`pool.json` 同理应拆为「随包池（只读）」+「用户池（可写）」两段 | 承 B18 的池契约（单池）；仓库自有规则：软件自带素材与用户内容分离 |

### 1.4 硬约束（不得偏离）

1. **几何层零 diff**：`shell-pet-geometry.js` / `shell-pet-drag.js` 不得出现在 `git diff`。
2. **随包素材只读**：`assets/pet-anim/webm/**` 与 `assets/pet-anim/pool.json` **零改动**（用户动作落**用户池**）。
3. **产物必须真带 alpha**：校验不通过 ⇒ **明确失败**（可读原因：无 alpha / 尺寸超界 / 时长越界 / 体积超界 / 编码不可解），**不得静默降级**（否则桌面上会出现黑底方块）。
4. **安全（解码不可信文件）**：对用户文件设**体积 / 时长**上限 + 超时中止 + 失败不留半成品；**不得**把用户文件当可执行输入。
5. **失败不破坏现状**：导入失败 / 半成品 / 池数据非法 ⇒ 桌宠行为**与今天逐位一致**（承 B18 三级回落）。
6. **降级面**：ffmpeg 不可用（未随包 / 被系统拦）⇒ 入口**明确告知**并退回「只收已带透明的 webm」这一最小形态（1.5 U-1 的 v1）。
7. **零新依赖**：**本批为唯一例外候选**（U-2 待裁定）；若引入，必须 ① 记入 `THIRD-PARTY-NOTICES.md`（许可 + 来源）② 体积入包体积登记 ③ 平台面（win/linux/mac）各自可行性说明。
8. **行宽 ≤300（不含行尾 CR）· 代码档 ≤500 行 · 文件头标准形**；新增渲染/主进程档须登记 `build.files`。

### 1.8 用户裁定（2026-09-18 · 本批范围改向）

用户原话：

> 「好，做的时候注意添加一个管理员身份入口，不要让所有用户都能添加解析，只有我才可以添加动作，**或者就不坐在 app 里面，我指定哪个视频直接让你解析**，你觉得呢」

主 agent 判断（记档，供评审与后续批次引用）：

1. **「管理员入口」在桌面应用里不是权限**：用户本就拥有本机程序（可改配置 / 拆包）⇒ 隐藏 ≠ 限制；写进需求会变成一句**假承诺**。若目标只是「不给普通用户添乱」，正确形态 = **不做入口**。
2. ⇒ **本批采纳选项 B：不进 app**。动作生产 = **仓内维护者工具链**（= R15 的 C 面），一条命令跑通：**抠像 → 归一化 → VP9-alpha 编码 → alpha 校验 → 入 `assets/pet-anim/webm/` + 写 `pool.json`**；输入 = 用户指定的源视频（绿幕或已透明）；工具链**不进发行包**（与 `node-runtime/` 同先例）。
3. **用户面导入（原 §1.2 的范围）降为后置需求**：保留台账 R18 与待决 U-1…U-6 备查；若日后要做，按 U-1 的 **v1（只收已带透明的 webm）**起步，ffmpeg 随包与否另裁。
4. **本批同时吸收 B18 §6.6 的一条观感证据**（对本批的提示词面有约束）：样本通用前缀明文要求「**第 10 秒必须完全恢复第一帧姿态**」⇒ 每段头尾各约 1 秒站定 ⇒ 硬切两段即出现 **≈2 秒静止**（= 用户所感「切换间隔感」的成因）；**新造动作的提示词必须沿用该约束**（拆接缝才有可重叠的余地，B21 才能做丝滑衔接）。

### 1.9 ffmpeg 获取方式（用户裁定 2026-09-18）

用户原话：「**从 ffmpeg 取**」。

- **源**：ffmpeg 官方站（`ffmpeg.org`）的 Windows 构建入口——其官方链接指向 **gyan.dev** 与 **BtbN（GitHub Releases）**；`download-ffmpeg.js` 取其一并**记录来源 URL + 版本 + SHA256**（可复现；不自行指定非官方镜像）。
- **形态**：与 `node-runtime/` 同先例——落 `tools/pet-anim/ffmpeg/`（**git-ignored、不登 `build.files`、不进发行包**）。
- **许可**：gyan.dev / BtbN 的 Windows 静态构建通常为 **GPL 构建**；**本工具链不随包分发** ⇒ **不触发 GPL 分发义务**。**复议条件（写明）**：若将来改作 app 内功能或随包分发 ⇒ **必须改用 LGPL 构建**（记入 §1.5 U-2）。
- **可复现**：脚本未取/失败 ⇒ 工具链给**明确提示 + 非零退出码**，不静默降级（与 §1.4-6 同口径）。
