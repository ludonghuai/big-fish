### 1.3 已确认的需求结论

App 更新下载完成的安装包**须被回收**，不在磁盘累积（真实安装包约百 MB 级，每次更新留一份）。回收**时机须安全**：安装器运行期间其自身可执行文件被 Windows 锁定，此刻删除既会失败也可能破坏正在进行的安装。

### 1.4 主 agent 的技术裁定

用户授权「要清理安装包」。据此主 agent 裁定回收时机 = **下次启动的 `startupCleanup`**（而非安装拉起后即时删）：

1. 即时删与安装器运行期重叠——Windows 对运行中的 exe 加锁，删除会失败（best-effort 吞掉）或危及安装；启动清理天然居于「安装器已结束」之后。
2. 失败面可控：启动清理本身是 best-effort，文件若仍被占用则下次启动再删，不阻断启动、不报错打扰。
3. 覆盖面：`userData/updates/` 下的**全部**文件（含已完成的安装包与半成品 `.part`）——该目录的唯一用途就是暂存下载产物。
4. 不改变既有语义：fail-closed 校验、失败可重试（重试即重新下载）均不受影响。
