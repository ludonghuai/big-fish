### 1.4 范围（做 / 不做）

**做**（八个面，逐面成文；面内顺序按「先总览后细节」）：

1. **进程与窗口模型** —— 主进程 / 4 个 preload（`pet` / `exchange` / `market` / `update`）/ 5 个渲染页（`pet` / `exchange` / `market` / `update` + 托盘）各是什么、生命周期、通信面。
2. **`shell-*` 16 档的角色与依赖方向** —— 逐档一句话角色 + 依赖图（谁注入谁 · 有无环 · 谁被 `main.js` 枢纽装配）。
3. **数据面（`~/.dsh`）** —— 每一类落盘物：**谁写 · 谁读 · 生命周期**（含 `storages/` / `profiles` / 会话记录 / 更新快照 / 配置）。
4. **IPC / 注入面契约** —— 4 个 preload 面的暴露形状 + 各模块的注入面（依赖注入的实参表）。
5. **桌宠子系统关系图** —— 几何 / 拖拽 / 动画链 / 物理 / 工作状态 五块的**关系与数据流**（**回指** `PET-*` 五档既有设计档，**不重述**其细节）。
6. **8 档探针清点** —— 每个探针：干什么 · 怎么跑 · 读什么 · 产出什么（R11 ② 的原始点名项）。
7. **构建与发布面** —— `build.files` 白名单机制（43 条扁平路径 + 加档纪律）/ `afterPack` / `make-icons` / `make-latest` / `download-*` / 更新链（App 本体 · Harness · 插件 三角）。
8. **插件 · 技能 · bundle 三面** —— 三者区别 · 装配关系 · 更新路径（回指 `SHELL-UX` / `AUTO-UPDATE`）。

**不做**（明确边界）：

- **不设计新功能**（纯现状记录）；**不改任何代码**（零代码批）。
- **不重述**既有设计档已详述的机制 —— **只回指**（D2 单一权威源）。
- **不做目录搬迁**（→ **B15 仓库卫生**）；**不写用户手册 / 使用说明**（→ `使用说明.txt` / `版本说明.txt` 既有面）。
- **不修发现的问题** —— 发现问题 ⇒ 登记台账（**本批只记录，不修**）。

### 1.5 硬约束（不得偏离）

1. **只写现状**：每一条事实带**证据行**（`file:line` 或实测命令）；as-of 标注（本仓行号易漂 → 明确「行号只作 as-of 参考」）。
2. **单一权威源（D2）**：既有设计档已详述的 ⇒ 本批**只回指不重述**；本批新详述的 ⇒ 他处只引。
3. **形式**：先出**总览档**（进程 / 模块 / 数据 / 依赖四张图 + 指针表）；**是否拆面档由设计者判定并说明理由**（模板：一主题一档）。
4. **落点**：`docs/design/<TOPIC>.md`（一主题一档）；**地图行由主 agent 登记**（设计者不写地图）。
5. **零代码改动**：不碰任何 `.js` / `.html` / `package.json` / `assets/**`（探针的**文档化** ≠ 改探针）。
6. **人类可读**：行宽 ≤300；图用 ASCII（先例：`PET-ANIMATION.md` §2.7 的注入面图）。
7. **行锚纪律**：引用的行号标 as-of；**不写「见上 / 见该节」式相对指针**（D4）。
