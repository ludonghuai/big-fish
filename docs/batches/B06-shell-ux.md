### 1.2 任务来源（用户原话，2026-09-16）

> 「我们接下来整合项目启动的问题，现在启动项目就会自动出现浏览器和harness项目，太冗余重复了；右下角的托盘右键不好用，为什么更新会显示只有安装版可以使用？不要做这个显示可以吗？；我们需要彻底整合一下，否则不符合用户习惯，把切换模式放在二级菜单不好用」

> 「右键大鲸鱼还会同时出现harness和喂养界面，非常不符合逻辑」

> 「新手启动界面能不能直接删掉？太废物了，因为harness里面就有api入口吧？」

> 「托盘不加，有harness的设置就可以了；托盘右键不好用是设计问题，应该出现哪些，顺序如何，不符合人类视觉习惯；左键打开harness，右键打开喂养怎么样？；导向窗用不着；dev下面不能使用同样的功能吗？；main要拆分，但是你要拆的合理」

> 「app不自更新，不可能比我开发还快；harness为什么还是旧的？你觉得有必要替换成新的吗？」

> 「安装版的肯定是要留的，否则用户没法更新；要换新版的，你可以自由安排任务顺序；保留自更新，你的建议可以，开工」

### 1.4 主 agent 的技术裁定

- **R1 落点**：本批属**新板块「桌面壳（SHELL）」**——启动形态 / 托盘 / 窗口 / 桌宠交互入口 / 更新门禁同属"壳"的用户面。`docs/requirements/SHELL.md` + `docs/design/SHELL-UX.md` 由 eng-designer 新建；`docs/README.md` 地图登记由主 agent 收口时补。
- **R2 启动形态（待用户在设计评审时追认）**：冷启动 = **桌宠（鲸鱼模式）+ 托盘**；主窗口**不自动显示**。**注意**：后端（`startDsh()`）仍须照常启动（本批只改"是否显示窗口"，不改"是否启动后端"）。
- **R3 桌宠左键语义**：**只开不隐**——点击桌宠一律"显示 + 聚焦"主界面，不做 toggle（避免"想打开却把它藏了"的误触）；隐藏主界面走托盘项。
- **R4 dev 门禁**：dev 下（a）托盘不出现 App 自更新入口、不弹「只在安装版可用」；（b）harness 检查 + 更新放行；（c）dev 的 `dshBinPath()` 改读活跃指针（与打包分支同口径），使 harness 更新在 dev 可验证。安装版行为不变。
- **R5 托盘草案作为设计基线**（eng-designer 可优化但须给理由）：一级 ≤ 12 项；分组 = 高频动作 → 外观与模式 → 功能与设置 → 危险操作（「高级」子菜单）→ 退出；「新手向导」项随 C2 删除。
- **R6 顺序裁定**：**B06（本批）先做**；**harness bundle 升级另立 B07**（前置 = 依赖脚本 / 锁文件那摊收口；须冒烟：dev + 打包各跑一次 + 插件装/卸一轮；保持精确钉版本，不放开 `^`）。
- **R7 拆分边界**：`pet.*`（B01/B03 纪律）· `updater.js` / `harness-store.js`（B02/B04/B05 纪律）**只搬不改**——拆分为纯结构迁移，任何行为改动都按回归处理。
