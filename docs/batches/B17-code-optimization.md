### 1.4 范围（做 / 不做）

**做**：① **并行热点消解**（`main.js` / `PET-ANIMATION.md` / `SHELL-UX.md`——拆或绑定口径由设计轮给选型 ≥2 + 否决理由）② **fanout 六档降到 ≤3** ⇒ 按销账条件删除 `baseline.json` 的 `fanout` 节（**门禁从此零存量豁免**）③ **T25 文件头迁移** ④ **T42 两重保障**。

**不做**：① 不夹带功能 / 不改运行时可观察行为 ✗（T42 的判据面除外 ✓）② 不顺手改设计档的**语义**内容（只动指针 / 结构面 ✓）③ 不引入构建链大改 / 新工具链 ✗（B11 口径不变 ✓）。

### 1.5 硬约束

1. **行为零回退**：三道门（lint / test:full / test:integration）+ 既有桩测全绿；fanout 消解不得以「改 require 为动态」等规避判据（判据句 = 超出者走 `init(deps)` 注入 ✓）。
2. **顺序**：建议**排 B15 之后**（B15 = 搬档类 ⇒ 两批同动结构会打架 ✗）。
3. 单档 ≤500 行 / 行宽 ≤300 / 文件头标准形。
4. 每处结构性改动须带**行为等价证据**（桩测 / 计数桩 / 亲 grep）。
