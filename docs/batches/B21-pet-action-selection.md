## §1 立案（主 agent）

### 1.1 目标（一句话）

让桌宠的动作**该来的来、该走的走**：她自己演的动作（**个人动作**）与你触发的动作（**交互动作**）**分工明确、互不打断错乱**，动作之间**衔接丝滑**（不再"一顿一顿"），并且**拖到屏幕边不再乱切成跑步**。

### 1.2 任务来源（用户原话，2026-09-18）

> 「动作直接会有切换的间隔，是因为没有一个动作开始与结束的状态让它丝滑链接；是的，是有交互的；动作非常丰富；但是**拖到边界的时候触发逃跑动作不太对，动作没正确切换**，我们要考虑一下鼠标点击的时候是否需要切换到交互动作，**区分交互动作与个人动作**，交互动作就比如**拖到边框逃跑，喂养**等等，个人动作是**它自己演示**的」

### 1.3 现状实测（勘察，2026-09-18）

| 面 | 实测事实 | 证据 |
|---|---|---|
| **问题①：切换有"间隔感"** | 19 次切换的 `shown` 间隔全部 ≈ 段长（min 254 / max 10052 ms，**超段长 0 次**）⇒ 技术上**无空白帧**（`ended→shown` 仅 16–29 ms）⇒ 观感成因 = **硬切 + 剪辑自带起收势 + 180 ms 淡入过短**（**无段间重叠**） | 主 agent 亲读 `%APPDATA%\bigfish\pet-anim.log`（B18 §6.6 已落档）；双缓冲机制见 `pet-chain.js`（两 `<video>` + `.is-front` 交叉淡入） |
| **问题②：`moves.run` 槽高频连切** | 切换 #15–#18 间隔 = **2952 / 635 / 1060 / 816 ms**；日志两行 `anim slot key=moves.run pick=原地左转奔跑 exclude=原地左转奔跑` ⇒ **该槽仅 1 段**，`exclude` 排除自己后仍只能选它 ⇒ 反复同段 + 高频打断 | 同上日志；池结构 = `assets/pet-anim/pool.json` 的 `moves.run`（1 段）· `moves.walk`（3 段） |
| **池与分类现状** | `weights {idle:10, turn:5, move:0}`；动作组 = `idle`(3) / `turn`(1) / `moves.walk`(3) / `moves.run`(1)；分类 = 小动作(18) / 玩耍(27) / 吃什么(12) / 时节(21) / 文字(2)；事件档 = happy / eat / sleep / read / starry / scared | `assets/pet-anim/pool.json`（71 行） |
| **交互触发面现状** | 点击 → `events.happy`（避开连播）· 喂食 → `events.eat` · 走路 → `moves.walk` · 跑步 → `moves.run` · 睡眠 → `events.sleep`（`loop=1`）· 拖拽 → **无专门档**（用户预期有「逃跑」类） | B18 §2.2.3 / §5.6（`slot-*` 日志）；样本侧有「被鼠标拖拽悬空反馈」段（池内有此素材名） |
| **素材面** | `assets/pet-anim/webm/` 106 段（**只读**）；池引用 91 段 / 未引用 15 段（工作状态 5 → B19；余额 6 / 碎碎念 3 → D2；拖拽 1 → **本批候选**） | B18 §5.4 |
| **既有机制（不得推翻）** | 双缓冲无空白帧 · 池校验 V1–V6 · 三级回落 · `prefers-reduced-motion` 四项 · 事件档避重（`nextInSlot` 契约保留） | `docs/design/PET-ANIMATION.md`（B18 段） |

### 1.4 硬约束（不得偏离）

1. **几何层零 diff**：`shell-pet-geometry.js` / `shell-pet-drag.js` 不得出现在 `git diff`。
2. **素材本体只读**：`assets/pet-anim/webm/**` 不得增删改（本批只改**池数据**与**选择规则**）。
3. **零空白帧不得回退**：B18 的 AC4 机检面（切换全 `readyState=4`、无禁用形态）必须保持全绿——**"衔接丝滑"不得以牺牲"无空白帧"换取**。
4. **PNG 通道零回退** + **零新依赖** + 新增渲染档须登记 `build.files`。
5. **默认行为保守**：衔接参数与交互档的引入若改变既有观感 ⇒ 默认值须显式裁定（1.5 U 项）。
6. **行宽 ≤300（不含行尾 CR）· 代码档 ≤500 行 · 文件头标准形**。
7. **许可面沿用 B18**（素材禁商用 + 三处署名在位，不得改写）。

### 1.5 待决项（须裁定后才能定稿设计）

| # | 待决 | 备选 | 影响面 |
|---|---|---|---|
| U-1 | **点击是否切交互动作** | ① **切**（点即有反应，推荐）② 不切（个人动作不被打断） | 交互/个人分类的核心语义 |
| U-2 | **打断规则** | ① 交互动作**可打断**个人动作 ② 个人动作演完再切（延迟响应） | 手感 vs 连贯 |
| U-3 | **拖到边框的"逃跑"档** | ① 新立 `drag` 类交互档（引用池内未引用的「被鼠标拖拽悬空反馈」）② 复用一个既有档 | 素材利用 + 语义准确 |
| U-4 | **衔接方式** | ① **段间重叠交叉淡入**（提前 N ms 起下一段，双缓冲已具备）② 加长淡入（180 ms → 更大）③ 段尾对齐（挑"起势/收势"匹配的段） | 观感（需实机调参） |
| U-5 | **单段槽的处置**（问题②的根治） | ① `exclude` 失效时**改用基槽**（如 run → walk）② 扩该槽段数（选段 = 数据面，但素材受限）③ 该槽**加冷却**（最小驻留时长） | 数值与规则 |
| U-6 | **个人动作的最小驻留** | ① 引入**最小播放时长**（如 ≥3 s 才允许被打断）② 不加 | 与 U-2 联动 |
