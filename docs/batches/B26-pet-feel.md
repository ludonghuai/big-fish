## §1 立案（主 agent）

### 1.1 目标（一句话）

**让「她正在干活」看得出来**，并**让落地踩实** —— 三条实机观感缺陷的最小修正批。

### 1.2 任务来源（用户原话）

> 「工作模式的时候会**穿插其它模式的动作**，导致动作不明显，交替起来看不出来在工作」（2026-09-18）

> 「重力模式弹跳不真实，**距离边框有一点的距离**，我觉得应该**完全等于边框**，这才真实」（2026-09-18）

> 「应该修，你的建议可以的」（2026-09-18 批准开工）

### 1.5 硬约束（七条）

1. **不对既有行为做无关改动** ✗：`shell-pet-geometry.js` / `shell-pet-drag.js` / `pet-chain.js` / `pet-chain-core.js` / `assets/**` = **冻结面**（逐档 `git diff` 为空）。
2. **零新增依赖** ✗（`dependencies` / `devDependencies` 零 diff）；不用新框架 / 不引第三方。
3. **行宽 ≤300**（不含行尾 CR）· 单档 ≤500 行 · 新增行不得把既有档推过上限。
4. **文档三层齐**：需求档（`docs/requirements/PET.md` 用户故事）+ 设计档（`docs/design/PET-ANIMATION.md` / `PET-MOVEMENT.md`）+ 本档 §2 任务书；**三方条目一致**。
5. **每条功能性需求 ≥1 用例**（正常 / 边界 / 异常），验收标准逐条回指。
6. **禁散文锚** ✗：断言只写行为面（业务可观察）与结构机检面（设计档 §2.8.4 同口径）。
7. **排期**：本批与 **B16（测试与门禁）** 写域**不重叠** ⇒ 可并行；与 `pet-chain-core.js` 相关的批次（B21 / B23）**不并行** ✗。

### 1.6 不做（范围外，逐条）

- **不动手感常数**（`restitution` 0.55 / 起飞门 T 等）—— 用户本次未提手感意见 ⇒ 维持现状；调 = 一处常量（既有「可逆变」设计 ✓）。
- **不做** 12 段未引用素材的接入（余额 / 碎碎念 / 拖拽悬空 / 工作状态 2 段）—— 归 **D2 面 / B22**（既有登记 O-17）。
- **不做** `pool.categories.weight` 的运行时消费面（是否真被选段消费 = **待核**，另立条目）。
- **不做** 六档工作状态（等待 / 成功 / 失败）—— 归 **B22 事件桥**（R17）。
- **不做** 时节的日期门 —— 归 **B23**（R16 时节门）。
