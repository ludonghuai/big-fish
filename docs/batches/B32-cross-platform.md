# B32 —— 跨平台可用性（linux 先做透 · mac 后置）

## §1 立案（主 agent）

### 1.1 目标（一句话）

**在 Windows 之外建立「装上能用」的可用性**：linux 侧完成「构建 → 安装 → 启动 → 托盘 / 桌宠 / 通知 / 更新」全链实跑并判据化；mac 后置（需 Apple 证书，见 R13 裁定）。

### 1.2 任务来源

需求池 **R13 跨平台可用性（win / linux / mac）**（用户 2026-09-17 提出）；**平台集合已裁定（用户 2026-09-17）= A**：win + linux 先做透，**mac 后置**。

### 1.3 现状实测（证据，接台账原文）

| # | 实测 | 证据 |
|---|---|---|
| 1 | 构建目标已配：`electron-builder --win/--mac/--linux`（nsis / dmg / AppImage+deb），`package.json` scripts 齐备 | `package.json` scripts（as-of 2026-09-19） |
| 2 | 发布 / 更新通道**实跑过 win32**（B08：钉版 + `bundle:check` = `action=none`）；linux / mac **未构建、未实跑** | 台账 **T10** / **T11** 行；`latest.json` 结构含三平台但仅 win 侧有实证 |

### 1.4 范围（做 / 不做）

**做**：① linux 构建（AppImage / deb）② linux 全链实跑（安装 → 启动 → 托盘 / 桌宠 / 通知 / 更新检查；含沙箱与路径差异）③ 差异清单与修复（判据化 + 证据行）④ 发布侧（`latest.json` 的 linux 条目 + 上传路径）——**与 T11 的用户手动步联动** ✓。

**不做**：① mac 构建 / 签名 / 公证（**后置** ✗——需 Apple 开发者证书；无证书则首启需手动放行 ✓）② 不改 win 面既有行为 ✗ ③ 不引入 CI 大改（linux 是否入 CI = 待决项 ✗）。

### 1.5 硬约束

1. 跨平台实现面**语义同源**、各面独立（不追求逐字一致；各面用自己的证据行 ✓）。
2. win 面零回退：三道门 + 既有桩测全绿 + `build.files` 白名单改动须逐条说明 ✓。
3. EOL / 文件头 / 行宽行数照规范档 ✓；新增平台分支须带**消解期**（承 NFR-7 先例 ✓）。

### 1.6 待决项（须裁定后才能定稿设计）

- **U-1**：**实跑环境**——本机为 Windows ⇒ linux 实跑需 WSL2（GUI / 托盘限制 ✗）/ 虚拟机 / 另一台机器，须用户定其一（**这决定本批能否闭环** ✗）。
- **U-2**：先做 **AppImage** 还是 **deb**（或两者同做 ✓）。
- **U-3**：linux 是否入 CI（`gates.yml` 现为 `windows-latest` 单平台）。
- **U-4**：mac 后置的**边界句**（哪些工作现在就预留：资源配置 / 图标 / 无签名的放行说明 ✓）。
