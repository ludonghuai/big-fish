# B30 —— 提醒面后续（重启误报修复 + 「等待确认」信号）

## §1 立案（主 agent）

### 1.1 目标（一句话）

修掉「每次重启 app 都会误报一次任务完成」（T40），并给「回合在等你确认」补上正确信号（R12）——两条都在提醒判定面。

### 1.2 任务来源

**T40**（用户 2026-09-18 实机误报，主 agent 三段实证）+ **R12**（B09 设计期 U-13 提出；用户 2026-09-17 裁定 A：不并入 B09，另立需求点）。两者同族：**提醒时机与真实状态脱钩**（T40 = 把后端启动写入误判成完成；R12 = 「该你确认」缺位）。

### 1.3 现状实测（证据，as-of 2026-09-19）

- **T40**：重启 app（12:00:51）⇒ 后端自身启动写入 `DSH_HOME`（`storages/session_projcache/sessions/session-f098….json` +
  `sessions/…/session.v3.jsonl.zstd` + `storages/workspace.json`，实测 mtime **12:01:24**）⇒ 提醒模块把「启动写入 + 静默 8 s」判成任务完成 ⇒ 误报 ✗。
  判据面：`shell-notify.js:277` 阈值 + `:164` / `:171` 门回退；`main.js:53` `IDLE_NOTIFY_MS = 8 * 1000`。
- **R12**：现判定「回合在途 ⇒ 不提醒」正确（避开语义错误的「已完成」；`SHELL-UX.md` §2.2.12 `L-B09-1`）；缺「该你确认了」信号 ⇒ 需在判据面扩展。
- 注：台账 R10 行所述阈值「30 s」与实现（8 s）不符 ⇒ 该**文字**同步归 B14 ✓（已立案）。

### 1.4 范围（做 / 不做）

**做**：① 重启窗口内的启动写入不构成忙信号（或记启动前基线——见 U-2）；② 「等待确认」信号（判定口径 + 文案 + 节流）；③ 两处判据句落 `SHELL-UX.md` §2.2.12；④ 需求条目（`SHELL.md` §三）由设计轮落。
**不做**：① 不重开 B09 已收口面（AC17–AC19 逐字不动 ✗）；② 不改 B26 已收口的提醒节流口径（气泡三条件）；③ 不代做 R10 的归档条件（秒表验收 —— 用户侧独立 ✓）。

### 1.5 硬约束

1. B09 行为面不回退；2. 判定门对 `DSH_HOME` **只读**口径不变；3. 新信号必须**可机检**（判据 + 取证行）；4. 三道门 + lint。

### 1.6 待决项（须裁定后才能定稿设计）

- **U-1**：R12 语义——检测到什么 ⇒ 提醒什么（「回合在途且等用户确认」的判据面）；**触发时机**（一次 vs 重复）与**与「完成」提醒的互斥 / 共存口径**。
- **U-2**：T40 实现口径——启动窗口屏蔽 vs 基线重置（记启动前 `lastBusyAt`）——设计者给候选 + 理由。

### 1.7 关联台账与需求档

台账 **T40 + R12** → 本批；需求档 = `docs/requirements/SHELL.md` §三（待落——由设计轮落）；同族：R10（已收口待验收）· T33（读面谓词，若同轮动该面一并核）。
