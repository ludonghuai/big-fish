# B23 批次档 —— 动作解锁规则：时节 / 饭点 / 等级 三把锁

> 六段制 · append-only · 一段一作者：§1 主 agent / §2 eng-designer / §3 设计评审 / §4 主 agent / §5 eng-coder / §6 主 agent。
> 本档 = **本仓原创需求**（**非**外部项目移植面）——台账 **R16**；承 B18 的池机制（池 = 数据面）。
> 用户 2026-09-18 原话：「时节的动作要根据电脑的系统时间判断，如果处于某个时节的前一周到后三天，就启动该动作，其他时间封闭不解锁」「吃早午晚饭也是一样的看时间，到饭点前后就出现」「等级也会解锁动作，你根据合理性来判断几级解锁哪几个…最好看丰富的动作需要更高等级，让玩家有获得感」。

## §1 立案（主 agent）

### 1.1 目标（一句话）

让桌宠的动作池**随"时间"与"你的陪伴"生长**：**节日到了**她会做节日的事（其余时间**锁着**）、**到饭点**她会吃饭、**好感度升级**会**解锁新动作**——看得见的"她越来越丰富"，让用户有收获感。

### 1.2 范围（做 / 不做）

**做**：
- **三把锁**（可选集 = 三者合取）：
  1. **时节门**：系统日期落在某节日 / 节气的 **`[节前 7 天, 节后 3 天]`** 窗口内 ⇒ 该时节动作**解锁**；**其余时间锁死**（绝不入选）。
  2. **饭点门**：系统时刻落在三餐窗口内 ⇒ 对应「吃早餐 / 吃午餐 / 吃晚餐」解锁；**一天一次**（同饭点演过即不再出现）；**过点不补**。
  3. **等级门**：好感度等级 ≥ 该动作的解锁级 ⇒ 解锁（映射表 = §1.5 的表，用户 2026-09-18 已确认）。
- **可选集计算**（纯函数）：`eligible(pool, {now, level}) → 可入选段集合` ⇒ 喂给既有链的选段（**锁住的段绝不入选**，机检面）。
- **解锁提示**：等级提升 / 节日解锁时给一次可见提示（形态待定，见 1.6 U 项）。
- **开关**：整套可关（默认值待裁定）。

**不做（本批出批）**：
- **动作图鉴面板**（能看到锁定项剪影 / 收集进度）——**另立批**（用户已同意分两步：先门控 + 提示 ✓）。
- 抽卡 / 成就 / 任务系统 · 云同步与网络校时（**时间源 = 本机系统时间**）· 多宠物共享进度（E 面）。
- **不改**：`assets/pet-anim/webm/**`（素材本体）· `shell-pet-geometry.js` / `shell-pet-drag.js`（几何冻结面）· B18 的池校验 V1–V6 与双缓冲形态 · B19 / B20 / B21 各批契约。

### 1.4 硬约束（不得偏离）

1. **几何层零 diff**：`shell-pet-geometry.js` / `shell-pet-drag.js` 不得出现在 `git diff`。
2. **素材本体只读**：`assets/pet-anim/webm/**` 不得增删改（本批只动**池数据**与**选择逻辑**）。
3. **锁住的段绝不入选**：门控必须是**硬排除**（机检：锁定段名在运行期 `pick=` 行中零出现），**不是**权重调零（调零仍可能入选 ✗）。
4. **时间源 = 本机系统时间**（不做网络校时、不做时区服务；跨时区以本机为准）。
5. **表的到期条件必须写明**：农历 / 节气表覆盖 **2026–2035**；到期后须刷新（**禁**"永久先例"）。
6. **Lv.1 必须够丰富**（硬约束）：新用户若因为等级门而觉得桌宠**单调** ⇒ 本功能失败 ⇒ Lv.1 的可选集须**≥10 段**且含至少 1 段"惊喜段"（见 §1.5）。
7. **默认行为保守**：三把锁的默认开关状态须显式裁定（1.6 U-4）；**关掉时与今天逐位一致**。
8. **零新依赖** + 新增渲染档须登记 `build.files` + 行宽 ≤300 / 代码档 ≤500 / 文件头标准形。
9. **许可面沿用 B18**（素材禁商用 + 三处署名在位，不得改写）。
