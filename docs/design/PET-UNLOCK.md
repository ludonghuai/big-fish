## 1. 需求层

### 1.1 总体需求（一段话定位）

让桌宠的动作池随「时间」与「陪伴」生长：**节日到了**她做节日的事（一年只此一窗，其余时间锁死）、**到了饭点**她吃饭（一天一次、过点不补）、**好感升级**解锁新动作（10 级对 10 档）；用户随时能在右键弹窗的**动作图鉴**标签卡里看到每条动作的名字、解锁条件（可读中文）与解锁百分比。三把锁全部可关、**默认全开**（用户 2026-09-20 裁定——装完即进入解锁玩法；关掉 = 该门来源不做过滤）；锁住的段**绝不入选**（硬排除，非权重调零）；时间源 = 本机系统时间（零网络校时）。

## 2. 设计层

### 2.1 问题陈述

既有链（B18 `pet-chain-core.js`）的选段是**无状态全池抽样**：`rollKind` 掷出 kind 后 `pickWeightedCategory` 按权重抽分类、`pick` 抽段名，池内所有段在任何时刻都可能入选。B23 要在这条链上游加一个**门**：按系统日期 / 时刻 / 好感等级把不可入选的段**硬排除**，并把「什么锁着、什么开着、进度多少」以可读方式呈现给用户。约束：不破坏 B18 池校验契约（V1–V6、双缓冲）、不改 B21 交互优先级与 B27 静默期、判定可测试（不靠等真实节日）。

### 2.3 图鉴形态与 U-6 决断

- **形态**：`exchange.html` 单窗口改**双标签卡**（顶部两个 tab 按钮：「喂养」= 既有全部内容原样迁入、「图鉴」= 新增面板）；默认停在「喂养」卡（右键打开行为与今天一致）；**不新建窗口**、不动 `openExchangeWindow` 的窗口参数。
- **U-6 = ① 不显示缩略图**（纯文字 + 名字）：本仓未迁入 `assets/preview/`（批次档 §1.7 登记）；② 抽帧方案需 ffmpeg（新依赖，硬约束 8）或依赖 B24 工具链（跨批耦合 + 串行）；③ 反向依赖 B24 = 本批被阻塞。三路均劣于纯文字，**否决 ②③**。
- **未解锁显示**（U-7 = ①）：显名 + 灰化（`opacity .45`）+ 条件串可见——用户能看到「差多少」（进度感的来源）；剪影方案（②）黑箱化条件，与「解锁条件可读」的需求本意冲突，否决。
- **排序**（U-9 = ①）：按分类分组（小动作 / 玩耍 / 吃什么 / 时节 / 文字——同池结构），组内按解锁级升序、时节组按节日表日期序。
- **条件可读化**（U-10）：等级门 = `好感 Lv.n 解锁`（**Lv.n = 运行时等级值**——等级阈值权威 = `affinity-core.js:15` `LEVEL_THRESHOLDS` 运行时读取，本设计与其数据档**零阈值数字**，B31 后刻度再调自动跟随）；饭点 = `早餐时段（06:30–09:30）一天一次`；时节 = 节日表中文串（如 `中秋：2026-09-19 至 2026-09-28`——表内逐条预生成，不运行期拼接农历）。图鉴卡与解锁提示**不得出现写死的「还差 N token」类旧口径**（B31 前刻度已作废——批次档 §2.2 F-1）。

#### 2.4.2 `userData/unlock-state.json`（运行期状态；主进程属主）

```json
{ "playedMeals": { "2026-09-20": ["breakfast"] }, "notified": { "level:3": true, "season:2026-中秋": true } }
```

- `playedMeals`：自然日 → 已演饭点（一天一次判据；读时按当日键取，旧键无妨保留或裁剪）。
- `notified`：已提示过的解锁集合键（一次提示判据）。
- 容错：解析失败 = 首次使用（同 `affinity.json` 形态）；写入 = 事件驱动（演过 / 提示后），不同步任何 tick 路径。

```
eligible(input) → { allowSet, lockedNames }                       // 可选集计算（核心入口）
  input = { poolNames, rules, now, level,
            switches: { season, meal, level },
            playedMeals, quiet }                                  // state 注入，now 可注入
validateRules(rules, poolNames)     → { ok, reason }              // 结构谓词 + 段引用闭合
```

- **双环境导出**（口径同 `pet-chain-core.js:225-227` 尾巴形态：node require + 可选 window 挂载）；**装载点 = 主进程**（核档由**组合根 `main.js` 绑定、经 `init(deps)` 注入** `shell-pet.js` / `shell-affinity.js`——两档零新增静态 require 边、判据 D② 扇出 5 / 3 不变；送达形态对比与理由 = §2.2.4 / §2.10；渲染层零新核，评审 #2 裁定）。
- **合取语义**：段入选 ⇔ 其所属每把门都放行——
  **时节段**（`seasonal` 命中）：时节门开 ∧ 当日 ∈ 窗口（D-2：时节段**只按日期锁、不按等级锁**——无 level 行，等级门对它恒放行）；
  **饭点段**（`mealActions` 命中）：饭点门开 ∧ 当刻 ∈ 窗口 ∧ 当日未演（等级门对它不设 level 行——唯一门槛 = 时刻 + 一天一次）；
  **普通段**（分类动作段）：等级门按 `levelUnlock` 判 `level ≥ 解锁级`。
- **关门语义（单一权威定义；评审 #1 裁定口径）**：**任一门关闭 = 该门来源不做过滤（等效该门不存在，即全解锁）**——
  时节门关 ⇒ 全部时节动作照常可选；饭点门关 ⇒ 三餐段照常可选；等级门关 ⇒ 普通段全部按已解锁处理。**全开 = 门控完整生效**（默认态）。
- **两层口径（复核轮 2 #3 裁定：集合面 vs 状态面——同一条内不得混写）**：
  ① **集合面（随开关走）**：`allowSet` 的**段名集合** = 各门放行段的并集；**三开关全关 ⇒ allowSet = 全池**（无门控形态，机检 TC-B23-18，**前提 = 当日无已演记录**）。
  ② **状态面（不随开关走）**：**「当日已演排除」（US-39 一天一次）是状态面约束，不在 `allowSet` 定义内**——饭点门关时该饭点段仍可选，
  但**当日已演过的饭点段照旧被排除**（US-39 本体语义；机检 TC-B23-19）。
  ⇒ 硬约束 7「关掉时与今天逐位一致」的实际口径 = **除 US-39 一天一次外逐位一致**（该例外面登记于此，唯一权威句）。
- **排除面**：eligible 输出的 allowSet 按**段名集合**表达；主进程据此对 `pool.categories[*].actions` 过滤后**空分类保留**（weight 照旧，抽中后无候选 ⇒ 既有 `pick` 退回原池逻辑**不得**用到——见 §2.5.3 过滤时机，锁死在「分类内段名过滤」而非「分类整删」）。

#### 2.5.2 时间语义

- 时间源 = `new Date()`（本机系统时间）；**判定函数不自行取时**（`now` 为入参——NFR-27 注入点）。
- 时节窗口 = 闭区间 `[节前 6 天, 节后 3 天]`（**含节日当天共 10 天**；窗口值在数据档逐条预生成，判定按 ISO 日期串含端比较）。
  **天数口径（S-4 订正；用户 2026-09-20 已裁：10 天 ⇒ 差额消解；登记 = §2.6 差异申报 ⑥）**：批次档 §1.2 用户原话「前一周到后三天」的字面读法 = 11 天（节前 7 + 当天 + 节后 3），与 D-2「一年只有 10 天」相抵；
  本批取 **10 天**（节前 6 + 节日当天 + 节后 3）——与已落地数据档、AC-B23-1 钉死端点（中秋 2026：09-19 / 09-28 为窗内沿点，09-18 / 09-29 为窗外沿点）逐字一致。
  **端点逐日列举**（以中秋 2026、节日本体 09-25 为例）：09-19…09-24 = 节前 6 天 · 09-25 = 节日当天 · 09-26…09-28 = 节后 3 天 ⇒ 共 10 个自然日。
- **跨年窗口合法（S-3 订正）**：窗口 = ISO 日期串对 `[起点, 终点]`，**校验只拒倒置**（起点 > 终点）；**跨年窗口按实况允许**——农历节日窗口可自年末伸入次年初
  （数据档实证：腊八节 `2028` 键 = `2027-12-29…2028-01-07`、`2031` 键 = `2030-12-26…2031-01-04`）；窗口键 = 该次节日的公历年份，
  判定 = 按该条目**全部年份键**取包含（`isSeasonOpen` 遍历 windows 全键，ISO 串序在跨年处天然正确）——**不得要求「按年切成两段」**（无此必要，且切段会与数据档形态相抵）。
- `tableExpiry` 过期 ⇒ 门控回落「无锁」+ 控制台告警（不崩、不静默成功——告警面 = console.error 一行）。
- 自然日 = 本机时钟 `toDateString()` 键（00:00 分界；跨日 / 休眠唤醒后按读时现算，不依赖计时器连续性）。
- **跨日检测落点（评审 #8）**：主进程在**每次重算点**（§2.5.4 触发面任一触发）以 `now().toDateString()` 比对上次自然日键（进程内单点状态）——键变化 ⇒ 先按新日键重置「当日已演」读面再组装 allowSet；判定同一函数、同一判据（`pet-unlock-core` 内 `rollDayKey(now)` 单点导出），不引入独立计时器（与 §2.5.2「不依赖计时器连续性」同源——无触发期的旧状态只在下一次触发时被现算覆盖，00:00–触发间无新播段可供饭点窗口外漏出，语义闭合由 TC-B23-7 断言）。

#### 2.5.3 与链的接驳（`shell-pet.js` 主进程侧 / `pet-chain.js` 渲染层消费）
