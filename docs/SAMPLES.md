## 一、`samples/` 是什么

`samples/` = **外部项目样本 / 移植参考区，非交付物**——放他人项目的代码或片段，供移植时对照参考；只读参考，不随本仓分发。

三条铁律（**详述处 = 本档**；违反即红，机检承载）：

1. **不被任何代码引用**——运行时 / 构建 / 脚本一律不得 `require` 或路径拼接指向 `samples/`（机检 = 判据 E①，检测三式）。
2. **不参与构建、不打进发行版**——`package.json` 的 `build.files` / `extraResources` 是显式白名单，**不登记 `samples` 即天然排除**；登记即红（机检 = 判据 E②）。
3. **第三方代码不入仓历史**——`samples/` 整目录 git-ignored（`.gitignore` 声明面）；他人代码的许可与污染面由「不入仓历史」承载。

判据句的**权威处 = `docs/CONVENTIONS.md` §四**（本档不复述）；机检 = `npm run lint` 的判据 E。

## 二、怎么加样本

- **放置**：`samples/<项目名>/`（顶层直放，一级目录即可；现例 = `samples/dsh-pet`）。
- **许可面注意**：他人代码的许可证不随本仓分发——样本不入 git 历史（铁律 ③），对外说明与发行版均不含样本。
- **不修改仓内档去适配样本**：完全解耦 = **双向不引用**——仓内代码不得引样本（铁律 ①），样本的存在也不得牵动仓内任何档。
- **永不**在代码里引用 `samples/`、**永不**把 `samples` 登记进 `build.files` / `extraResources`——判据 E 会拦（红面点名档:行或键）。

## 三、移植怎么走四步流程

把样本参考转化为本仓功能 = **移植需求，与一切需求同链**，四步不跳步（唯一详述处 = `AGENTS.md` §二）：

**需求 → 设计 → 开发 → 测试**——登记需求点（台账）→ 立案（批次档 §1）→ 设计评审 + 用户批准 → 实施 + 测试 + 批次 §6 核销。

- **样本自身只作参考**：移植产物须**本仓自研**（结构与命名按 `docs/CONVENTIONS.md`）；样本代码不搬进交付面（与铁律 ③ 同源）。
- 先例：R14（样本区落位，本批 B29 收口）· R15（动画链移植 A 面，B18 已收口）。
