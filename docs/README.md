# 文档地图 — docs/

本仓文档体系入口。新读者按「需求档 → 设计档 → 批次档」的顺序读。

## 一、落点约定

| 层 | 落点 | 说明 |
|---|---|---|
| 需求档 | `docs/requirements/<板块>.md` | 一板块一档；本仓板块 = 桌宠（PET）、自动更新（UPDATE）、**桌面壳（SHELL）** |
| 设计档 | `docs/design/<主题>.md` | 一主题一档，按「需求层 / 设计层 / 测试层 + 变更记录」组织 |
| 批次档 | `docs/batches/<批次号>-<主题>.md` | 按六段制组织，每段一位作者（append-only） |
| 提示词（产品代码，非文档层） | `bundled-skills/*.md`（5 个） | 随软件打包，经壳侧 `DSH_BUNDLED_SKILL_DIR` 环境变量注入后端（取值 = `bundledSkillDir()`；行号只作 as-of 参考：`shell-backend.js:102`，as-of 2026-09-17 实施后 —— B06 F6 拆分后由 `main.js` 迁至该档）；改动属产品代码，不走文档流程 |
| 台账（需求池 / 技术待办） | `docs/TODO.md`；归档档 `docs/TODO-archive.md`（按需生成） | 一条一行，不展开任务细节；需求池条目挂「需求档节 + 批次档 §2」、技术待办挂「归属档节 + 最小证据行」；`status` 六态（活文件只留未决四态），已决条目移入归档档 |
| 行宽约定（项目声明） | 台账 `docs/TODO.md` / 地图（本档）的**表格行**；批次档 **§3 设计评审段落** | 用户 2026-09-17 裁定 A（台账与地图的表格行豁免）与 **A′**（批次档 §3 豁免——该段是评审者逐字落档段）；**规则句、豁免面清单与判据口径（行长按不含行尾 CR 计）的详述处 = `docs/CONVENTIONS.md` §五——本行只留裁定记录，不重述规则** |
| 入口档（工程纪律） | 根 `AGENTS.md` | 前置于 `docs/`：写权矩阵 / 四步流程 / 门禁现状与目标 / 文档体系入口；只给指针，不重述别处全文（B11 落档） |
| 规范档 | `docs/CONVENTIONS.md` | 工程规范档（非板块需求）：代码形态的唯一权威句——文件头 / 命名 / 注释语言 / 注入面 / 行宽行数 / EOL 与空白 / 提交与变更（B11 落档） |
| 外部样本 / 移植参考区（**非交付物**） | `samples/`（顶层目录；**本地 git-ignored**） | 用户放置**他人项目**供借鉴 / 移植参考：**不被任何代码引用 · 不参与构建 · 不打进发行版**（`package.json` 的 `build.files` / `extraResources` 均为显式白名单，不登记即天然排除）；第三方代码**不入仓历史**（规避许可与污染）；**移植本体另立需求点、走四步流程**（台账 R14） |
